# Stage 2 / Stage 5 · 互动蓝图与滚动卷纲（PLAN-01 / PLAN-02）

本协议补充现有 story-architecture 与 R3 运行手册。不是独立命令，不引入外部工作台、额外审批或大量模板文件。旧模式仍按其正式审核协议；R3 使用严格分区、核心批准和卷级检查点。自然语言识别“继续规划”“第二卷怎么写”“这里改成……”即可进入相应步骤。

## 1. 作者可参与的全书蓝图

先读取已确认的故事选择和必要的知识库专题，保留已锁定条件。用 [创意竞标](creative-lab.md) 比较真正不同的冲突引擎；根据作者参与度提供候选或由 AI 在授权范围内拟定。围绕最重要的选择讨论：人物最终变成什么样、核心关系付出什么代价、冲突为何持续升级、世界限制怎样影响行动、关键承诺如何兑现。创意明确时不反复重问，不把一堆细节一次性丢给作者。

先给出完整因果梗概与终局方向（作者如不想提前看到全部剧透，可只展示必要选择，内部仍保留完整因果供审核，正式批准所指版本必须明确）。若关键冲突尚未解决，给 2–3 个有区别的修复方向，说明改变哪项规则、哪些人物及远期影响；仅有局部变化不重做全书。作者选择或委托后自然进入四级规划：全书→卷→弧→近章；远期允许调整，不把预测当事实。

## 2. 将参考知识融入现有四个文件

| 作者/规划需要 | 按需定位的专题 | R3 落点 |
|---|---|---|
| 主角/主角组/反派/关键关系 | topic character（含设定集模板） | 00 核心人设；远期人物变化入动态状态与远期弧线 |
| 世界、能力、势力、经济、技术 | topic world + 相关 CSV | 01 核心契约中的硬规则和限制；卷内尚未发生的变化入滚动区 |
| 复合题材 | topic fusion + route.referencePaths | 01 核心承诺与共同冲突，流派机制服务于世界和人物 |
| 全书梗概、卷路标 | topic outline + topic payoff | 01 核心必要因果、终局条件与滚动卷纲 |
| 伏笔与时间线 | topic foreshadowing/outline | 01 相应卷内 H4+ 节拍、时间锚、读者信号；真实发生后才进账本 |
| 叙事视角、声线、示范文风 | topic voice/prose | 03 文风指纹，真实写作后进入校准段落 |
| 章节范围、字数、稳定槽位 | 现有计划与门禁 | 02 原有 JSON 结构，不新增上游状态 schema |

读取专项原件的小节，转化为当前作品的具体因果和决策；不要复制整套模板或另建十四份工件。固定章数、危机次数、爽点比例、反派层级只是原件建议，不强制执行。适用字段缺失才补；与已确定故事无关的内容不填。

## 3. 当前卷互动规划

首次卷纲由核心方向推演；续卷先读取已完成正文的真实账本、当前人物/关系、资源时间、未回收伏笔和上一卷余波，确认下一卷范围及重要作者要求。已完成/已冻结内容保持原样。作者未要求细选时给出主线建议和关键取舍，不逐章请示。

在 01-大纲.md 的当前 `### 第N卷` 内，用 H4 及以下层级按需组织：
- 本卷开始状态、阶段目标、核心冲突、卷末不可逆新状态；主角和主要对手如何自主行动。
- 节拍：期待→行动与反制→局部兑现→实际代价/关系或资源变化→余波→下一期待。转折次数随题材，不固定三次危机。
- 时间线：相对日期/重要期限、关键事件间隔、资源/能力/信息依赖；悬疑另区分事实/人物解释/读者所知。涉及确定性数值时核算；不适用的项目不用硬造。
- 章纲：稳定 chapterNumber/filePath 槽位、章目标、人物选择/阻力/状态变化及与前后章的因果关系；近三章到可写场景级，后续逐弧细化。保留阶段兑现与约束，不写死远期每个场景。
- 新设定仅作为规划提案，属于核心硬规则的变更走原核心重审；局部卷内计划放对应卷。不得把未写正文的计划写成已发生事实。

展示给作者的是本卷故事、关键变化及必要取舍，不暴露长 JSON、检索日志或要求填写表格。作者说“加重某个人物戏份”时，说明受影响的情节/关系并调整当前合法可变范围；已批准卷或核心按原协议建立新 revision、真实复审/批准。没有权限修改时保留方案，不擅自覆盖。

## 4. 审核与验收边界

按 R3 严格分区保留原 H2/H3；所有新增结构使用允许的标题层级，稳定章节路径。R3 初次正式核心与卷准备、双独审及真实批准仍由 r3_plan.mjs 执行，正文仍由 v3_gate.mjs 判定；不因作者授权 AI 拟定或自然语言表示“继续”而推定批准当前版本。旧项目走原 plan_review 流程。只在必要确认点请求真实作者决定，不增加模板审批。

真实交互验收须在新独立项目中观察：作者提供一句话/完整构思/授权 AI 三种入口、是否不重复问、题材适配、选择对人物与冲突的具体影响、局部修改与中断恢复、无金手指现实题材、复合流派不污染世界；完整蓝图与卷纲须实际检查分区、时间/资源/因果及作者意图对应。只做规划时停在草稿或合法待批准状态，不生成正文，不制造作者消息或评审身份。工程测试只证明记录、路由及兼容性，交互质量和文学效果须宿主实测。
