# Stage 1 · 自然语言互动共创（INIT-01 / INIT-02）

此协议属于单一 Chinese Novelist Skill 的内部流程，不是新的 Skill 或用户命令。适用于新作品立项（包括 R3）；续写已有项目直接按当前项目状态路由，不重新做初始化。R3 仍为显式实验模式，既有 R2 不静默迁移。作者不需要知道内部脚本、题材标签、数据字段或审批命令。

## 1. 从意图开始，而不是从问卷开始

- 从自然语言、片段、现成大纲、题材组合或“没有想法”开始。先提取本轮与当前作品已明确的信息、作者明确锁定项、尚未决策项；不要借其他作品的偏好覆盖当前作者决定。
- 用统一知识库 route 确认世界、机制、流派与待解析标签，按当前难题调用 search/topic/entry。题材不明确时先提少量方向，不先强行选择题材或随机填满表格。
- 作者自由叙述优先。只有缺失会实质影响当前选择、产生高返工风险或存在真实冲突时才提问。普通轮次一个最有价值的问题；多项紧密相关且一起回答更省力时可合并。候选通常 2–4 个，各有不同阅读体验、代价与长期影响；作者可自由输入、混合、否定、跳过非关键细节或交给 AI。没有选择组件的宿主直接用对话。
- 从一句话启动：例如“仙侠+凡人+长生+家族”先问长生与家族的核心矛盾；作者已选择“寿命无限、修炼资质平庸”便不再问能力类型，下一轮优先讨论可死亡性、身份暴露或家族动机中最影响主引擎的一项。不要把未知条件当已确定事实。
- 自主模式：作者明确授权 AI 提出并选择细节，按授权范围填入建议；可以一次呈现完整候选与需要作者决定的关键分歧，不要求固定问答轮数。已有完整蓝图时只诊断实质缺口。授权规划不等于授权冻结、试写或批准。
- 参考作品是可选灵感源：只在作者提供可访问材料时拆解可泛化的阅读承诺、机制、人物冲突、叙事方法；区分原文证据、推断、转化候选。未读到不声称拆解；不复制人物/专有设定/独特表达，不自动采用未经作者认可的变体。市场现况需另行核实，知识库不是市场实时数据。

## 2. 动态采集主题（按需，不是必问顺序）

| 主题 | 核心判断 | 优先参考 |
|---|---|---|
| 灵感与定位 | 原创/参考；世界与玩法；目标读者及阅读承诺 | route、topic genre/market/creativity |
| 人物与矛盾 | 主角目标、选择、缺陷、关键对手与人物关系 | topic character、人物关系 CSV |
| 机制与规则 | 能力/社会/专业约束、可观察代价、信息边界 | topic world、流派参考、金手指 CSV |
| 差异化 | 哪些规则与人物命运不可替代，后续如何持续变化 | creative-lab、topic fusion |
| 规格与文风 | 预计篇幅/章长、视角、调性、限制、标题（可晚定） | topic voice、题材与调性 |
| 故事方向 | 终局方向、关键变化、希望保留的弹性 | story-architecture、topic outline |

悬疑优先谜题/证据公平/人物知情；现实职场优先职业责任与真实制度；经营优先投入产出和组织成员自主性；仙侠优先能力边界和资源；科幻优先技术限制与文明反馈；情感优先关系欲望与障碍。不强制女主、反派分层、金手指、货币、固定反套路数、固定章节数。作者可选择成熟类型，未知与“不适用”不同。

## 3. 轻量记录与恢复

在作者确认的独立新作品目录内（不得是 Skill 仓库或既有小说目录），宿主内部使用 r3_intake.mjs 保存唯一的 05-共创草案.json。若暂未授权文件路径，先自然对话，明确仅会话内恢复；不得声称已经持久化。目录可用时在每次有实质新决定后批量更新，不为每条闲聊生成文件。原始用户话语只记录必要的证据；不记录秘密或无关个人信息；不自动上传。普通项目备份自然包含草案。

内部工具（由 Agent 调用，作者不需输入）：
```sh
node scripts/r3_intake.mjs PROJECT init
node scripts/r3_intake.mjs PROJECT status
node scripts/r3_intake.mjs PROJECT update < PATCH.json
```

update 读取 stdin 的对象，例：
```json
{"baseRevision":0,"changes":{"world":{"status":"confirmed","value":"仙侠","source":{"ref":"实际可复核的作者消息位置","quote":"实际作者原话"}},"mechanism":{"status":"proposed","value":"寿命无限但仍可因伤死亡","basis":"长生机制与风险控制参考"}}}
```

字段：inspiration、world、promise、story、protagonist、conflict、mechanism、relationships、constraints、scope、ending、style、title。每项 value 为简洁自然语言（例如 scope 包含篇幅和章长）。未录入为 pending；proposed 是 AI 候选；confirmed 是作者实际认可；delegated 是作者明确委托（value=null 表示等待 AI 决定，填入后仍保留委托证据）；not_applicable/deferred 仅可用于可选项，必须有真实作者消息出处（可以是一次明确的批量授权/确认）。不把默认建议记作作者选择。optional unresolved 可由 Agent 判断是否影响当前题材，不作为统一硬门槛。即使 planningReady 为 true，只要当前题材依赖尚未解决的机制、关系或限制，也应先澄清或按真实委托拟定；不能直接把 unresolved 忽略。

status 返回已知、待定、AI 受托未完成、暂缓、依赖变化需复核等。只问影响当前决策的缺口；无必要不复问已确认项。改变世界/故事等上游条件后，保留原决定并列出受影响的下游项，重新核对必要处，未受影响的不动。工具保护作者已确认/委托项不被普通 AI 提案直接覆盖。单写手串行；revision 防止顺序中的旧补丁，原子替换避免半写；不声称真正并发 CAS。读取失败停止并报告，不静默清空。已有规划文件时草案只读，不能用它重写正式蓝图或当前账本。历史项目无草案不补造。

## 4. 由共创进入正式规划

- 关键选择已足够时，汇总一句话故事、读者承诺、核心人物及矛盾、机制与边界、作者限制和待定事项。明确哪些是作者锁定、哪些为委托方案。若有关键冲突先解决；非关键可暂缓。工具的 planningReady 只是必需文本字段的准备提示，不是批准或文学判分。
- 按 creative-lab 保留创意竞标；作者已有明确方案时以相容的不同展开路线为默认，作者明确要求直接采用完整构思或只需局部规划时不强制重开竞标，仍做必要的引擎诊断。展示取舍，不机械凑三案。
- 作者明确选择/确认创意方向后进入 Stage 2（可生成未批准蓝图草稿）。确认范围必须明确；不得用草案的 confirmed、delegated、planningReady 代替 creativeDecision、R3 core/volume/Pilot 的真实批准。
- 生成正式四份规划文件后，草案仅作历史决策依据，不成为第二份事实权威。进入 [互动蓝图与卷纲](interactive-planning.md)，沿用原核心/卷级冻结、独立审稿、真实作者批准及正文门禁。任何已有项目修改都走原版本协议，不用初始化工具改 canon。
