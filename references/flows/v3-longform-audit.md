# V3 连载与五章审计

前提：`node scripts/v3_gate.mjs check PROJECT 4` 成功。第4章起，每次认领章节仍执行 `check`；严格保持原版 `chapter-checklist.md` 的事实词典、摘要、人物知情、数字和文风基准维护。

## 连续写作

相邻、互为因果的章节以**串行**为默认；可以并行开展资料查证、反套路检验与独立审稿。不能在多个写作 Agent 同时盲改同一事实账本后假装无冲突。

- 有效变化不等于每章打斗；情节、认知、关系或后果的改变均可。
- 主角需要付出具体代价，允许非理性选择，但要符合人性和角色经历。
- 情绪压迫与回报由作品承诺和题材决定，不强制“压二章爽一章”。
- 长线秘密需要兑现，不允许用不断新增谜题掩盖旧承诺悬空。

## 每五章或一个故事弧结束

由独立编辑核对当前分组原文、历史事实账本、上一次审稿意见，记录至 `reviews/arc-NN.md`：

1. 时间、物品、资金、战力与角色已知/误解是否前后一致；
2. 承诺→铺垫→兑现的具体证据；未兑现有明确未来计划；
3. 人物是否拥有独立动机和犯错成本，配角是否成为纯嘴替；
4. **剧情机制去重**：重复的“受辱→发现漏洞→打脸→升级”、反派犯同种错误、重复反转或重复钩子；主题性呼应不等于机械重复；
5. 文风自然、对话差异、职业真实感与无效复述；
6. 三项以内最重要的修订措施、影响章节、复查结果。

重大结构缺陷必须暂停后续章节，先修订正文与账本。脚本可以检测文字完全重复，不能自动认定“剧情机制重复”或“人物有生命力”；这些需要文本证据和编辑判断。

## 作品质量验收

对同一题材、规格和核心设定分别试写 V2、V3 的前三章，隐去版本后由目标读者比较原创感、人物魅力、节奏和追读意愿。延伸10章并跨卷复测；**AI 自评分数不等于真实读者反馈**。
