# Agent Handoff Protocol

> **文档职责**：本文仅规定新 Agent 如何接管项目、承担什么角色、遵守哪些长期规则与如何完成接管验证，**不承担当前项目进度管理**。  
> **维护原则**：仅当接管流程、角色职责或权限规则发生实质变化时才更新本文；普通研发进度、分支切换、测试结果、版本升级与阶段推进，**不触发本文更新**。

### 文档职责边界
- **本文（[`docs/AGENT-HANDOFF.md`](./AGENT-HANDOFF.md)）**：长期稳定的角色定义、隔离约束与通用接管协议。
- **[`docs/PROJECT-CONTEXT.md`](./PROJECT-CONTEXT.md)**：全仓库背景、重要决策、当前阶段、最新状态、下一步及专项入口。
- **各专项 PRD**：具体任务要求、前置依赖与验收标准。
- **各专项 Progress Log**：任务状态变更、Commit、测试与验收证据的详细权威记录。

---

## 一、通用接管流程

新 Agent 接手项目时，按以下顺序只读核查后再开始工作：

1. **定位权威仓库**：确认当前工作目录指向项目公开主仓库 `chindden/chinese-novelist-skill`。
2. **读取项目上下文**：通读 [`docs/PROJECT-CONTEXT.md`](./PROJECT-CONTEXT.md)，掌握项目长期目标、作者原则、历史决策、当前阶段与下一步方向。
3. **核验实时 Git 状态**：检查当前所在分支、最新 `HEAD` 提交与工作区是否存在未提交修改；以实时 Git 状态为准，不将文档中的历史快照当作实时状态。
4. **按需读取专项文档**：根据上下文指引，读取当前活跃专项的 PRD、Progress Log、相关规范（如 [`docs/RESEARCH-ASSET-POLICY.md`](./RESEARCH-ASSET-POLICY.md)、[`docs/PROJECT-ASSET-INDEX.md`](./PROJECT-ASSET-INDEX.md)）以及已冻结的架构文档。
5. **汇报接管结论**：按本文第四节完成动态接管检查，向作者或审核 Agent 输出 `GO` / `NO-GO` 结论、依据与下一步动作。

## 二、角色与权限

### 1. 三方职责（通用角色）
- **研发 Agent**（当前由 Neon 承担）：负责工程研发、测试编排、子代理调度、实验观察、结果收集与技术分析。
- **审核 Agent**（当前由 GPT-6 承担）：独立核查代码、Diff、测试与实验依据，提出整改意见并负责最终验收。
- **作者**：负责产品方向、重要原则、重大变更与研发授权，保留最终决策权。

### 2. 研发 Agent 角色隔离约束
为保证创作与审稿实验的独立性和客观性，研发 Agent 必须严格遵守以下边界：
- **不亲自充当测试小说写手**；
- **不亲自承担测试小说的文学修改**；
- **不亲自充当独立审稿人**；
- 真实创作测试必须由独立的 **Writer 子代理** 执行；
- 文学审稿必须由独立的 **Reviewer 子代理** 执行；
- **Writer 与 Reviewer 必须是不同的 Agent，不能由同一个 Agent 兼任**；
- 研发 Agent 作为 **Observer**，不得为了使测试通过而临时补写正文、篡改审稿结论或绕过 Skill 既有流程，**不得通过临时增加提示、额外指导或人工补救来掩盖被测 Skill 本身的缺陷**；
- **若当前环境无法提供符合隔离要求的子代理，必须报告 `BLOCKED`，不得由研发 Agent（当前为 Neon）自行替代**；
- 若进行受干预对照实验，必须显式记录干预内容，并严格区分**零干预**与**受干预**结果；
- 工程单元测试、集成测试与代码实现仍由研发 Agent 执行。

### 3. 验收与决策分权
- 研发 Agent 最高只能将任务提交至 **`READY_FOR_REVIEW`**，不得自行标记为 `ACCEPTED`；
- 审核 Agent 独立出具验收意见（通过或要求整改）；
- 作者对产品方向、重大变更与关键研发阶段授权保留最终决策权。

## 三、长期工作原则

1. **以权威文件为准**：一切结论与状态以 GitHub 仓库及权威项目文件为依据。
2. **不依赖旧会话记忆**：不得假设新环境具备旧 Agent 的聊天记录、单一临时 VM 或非权威外部云盘凭证。
3. **严守授权边界**：不越权扩大任务范围、不擅自修改已冻结架构、不提前启动未获授权的阶段。
4. **严明证据层级**：不将架构设计、代码实现、测试通过与实际运行/文学质量验证混为一谈。
5. **按需保全、聚焦主流程**：当前任务直接依赖的必需证据优先保障；与当前任务无关的历史文件缺失，不自动阻塞研发推进。
6. **保护既有成果**：不擅自覆盖未提交工作、历史决策记录或已冻结成果。

## 四、接管验证（动态检查，不预填答案）

新 Agent 应在**不依赖旧聊天记录**的条件下，仅依据仓库实时文件独立回答以下 5 个问题：

1. 当前项目目标和重要原则是什么？
2. 当前处于什么研发阶段？
3. 哪些工作已经验收，哪些尚未完成？
4. 当前有哪些真正影响推进的风险？
5. 依照当前授权和前置依赖，是否可以继续研发？

完成核查后，简洁输出以下结论即可：
- **接管判定**：`GO` 或 `NO-GO`
- **判定依据**：当前分支、最新 `HEAD`、授权状态与关键前置条件核验结果
- **下一步动作**：当前唯一优先行动（若 `NO-GO`，则写明具体阻塞点与所需决定）
