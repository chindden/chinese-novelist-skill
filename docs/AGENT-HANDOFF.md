# Chinese Novelist Skill — Agent Handoff Protocol

> **版本**：`1.0` ｜ **适用范围**：`chindden/chinese-novelist-skill` 全仓库长期跨会话 / 跨 Agent 接管协议  
> **核心目标**：让任何新接手的 Agent（无旧聊天记录、无旧账号依赖）在数分钟内准确恢复项目状态、确认权限边界，并无缝推进当前唯一优先任务。

---

## 一、接管前强制检查（Pre-Handoff Checklist）

新 Agent 动任何文件或执行研发前，必须按序完成以下只读核查：

1. **确认仓库与分支**：核实本地/远端指向 `chindden/chinese-novelist-skill`（当前唯一公开权威主仓，不设第二个研发仓），确认当前活跃分支（当前为 `feat/r3-p0-controlled`）。
2. **检查最新 HEAD**：运行 `git log -n 5 --oneline`（或查 GitHub 最新提交），切勿把文档中的历史快照当作实时 HEAD。
3. **检查工作区状态**：运行 `git status -sb`，确认是否存在未提交修改或未跟踪文件；发现异常改动先汇报再处理，不得擅自覆盖或重置。
4. **按序阅读 4 份核心档案**：
   - [`docs/PROJECT-CONTEXT.md`](./PROJECT-CONTEXT.md)（全仓库历史、作者原则、决策边界与实时阶段）
   - [`docs/RESEARCH-ASSET-POLICY.md`](./RESEARCH-ASSET-POLICY.md)（按需保全原则、公私边界与四级资产分级）
   - [`docs/PROJECT-ASSET-INDEX.md`](./PROJECT-ASSET-INDEX.md)（关键资产位置、状态与按需恢复入口）
   - 当前专项管理 PRD（现阶段为 [`docs/r3/p0-implementation/README.md`](./r3/p0-implementation/README.md)、[`P0-Implementation-PRD.md`](./r3/p0-implementation/P0-Implementation-PRD.md) 与 [`P0-Progress-Log.md`](./r3/p0-implementation/P0-Progress-Log.md)）
5. **按需查阅冻结架构**：仅在任务涉及具体规格时读取 [`docs/r3/review-v3/`](./r3/review-v3/README.md)，**禁止无必要地重新研究或质疑已冻结架构**。

## 二、项目恢复必答项（8 项状态复述）

读完上述文档后，新 Agent 必须向作者/审核者准确回答以下 8 个问题，方可确认接管成功：

1. **项目要解决什么问题？**  
   让中文长篇小说写作 Skill 从“能够完结”演进为“持续写出让读者愿意追读的长篇作品”，统筹创作质量、长期记忆、多题材知识、审稿机制与工程效率（不以机械指标替代文学质量，不因死磕字数牺牲内容完整性）。
2. **当前采用什么创作和审稿架构？**  
   创作侧为 R3 “两级冻结（核心契约 + 卷级滚动检查点）· 滚动双环 · 完本精修”；审稿侧已按外部对标与离线校准教训完成 R3 审核体系 v3 设计（S1 四级枚举、写手语域防火墙、A/B/C 三方案离线对照、`precheck v2`、`G2-A`/`G2-B` 分离、L0 全书只读机械诊断、5 分钟独立 `Perf-Track`）。
3. **哪些架构已经冻结？**  
   `docs/r3/review-v3/`（`v1.2.3`，PR #3 合入 `feat/r3-migration` @ `b5572a94`）为只读冻结权威；`docs/r3/p0-implementation/`（P0 管理 PRD `v1.0.1`）已获 GPT-6 `ACCEPTED`。
4. **哪些能力已经实现并验证？**  
   R3 独立仓库迁移、GPL-3.0 许可调整、上游 722 条知识与 37 套模板只读 BM25 检索、自然语言共创/互动规划脚本、R2/R3 现有基线脚本与单测、`P1-08` 离线纯 Markdown 校验脚本。
5. **哪些能力只是设计或预测？**  
   审核体系 v3 全部 P0/P1 新组件（S1 四级枚举、语域防火墙、A/B/C 三方案胜出者、`precheck v2`、L0/L2/L3 闭环）、5 分钟单章端到端目标（`Perf-Track`）、跨题材普遍文学质量提升均处于设计/待验证态（`PENDING_VALIDATION`），**严禁标为已实现**。
6. **当前 P0 进行到哪一步？**  
   查阅 `docs/r3/p0-implementation/README.md` 与最新 Git 提交确认实时状态（截至本协议建档：`P0-0` ~ `P0-6` 均为 `NOT_STARTED`；本协议与 `PROJECT-CONTEXT` 经 GPT-6 验收通过后，`P0-0` 已获作者预先授权直接启动）。
7. **当前有哪些阻塞和风险？**  
   `G2-B Independent Holdout` 当前 `underpowered`（就绪 `0` 章 / `0` 案例，需在 `P0-0` 实测核查样本来源与缺口）；A/B/C 方案尚待离线独立对照；不把与当前任务无关的历史文件缺失误判为阻塞。
8. **下一步应该做什么？**  
   明确指出当前唯一优先任务（例如：当前等待 GPT-6 验收 `PROJECT-CONTEXT` + `AGENT-HANDOFF`；通过后立即启动纯只读 `P0-0`，输出 `P0-0-Baseline-Audit-Report.md` 并置为 `READY_FOR_REVIEW`）。

## 三、证据与资产工作铁律

1. **按需优先**：优先检查当前主流程与 P0 实施直接依赖的文件；**不强制恢复或搬迁与当前任务无关的历史实验**。
2. **不把无关缺失当阻塞**：早期废稿、已淘汰实验或非必需历史包缺失，不得自动视为项目阻塞；只有直接阻断当前任务的证据缺口才需登记并按需补充。
3. **证据分级严明**：严格遵守六层验证阶梯（设计 ≠ 实现 ≠ 单测通过 ≠ 实跑 ≠ 文学提升），严禁将设计/预测标为已实现。
4. **零孤岛依赖**：
   - 不依赖旧 Agent 的会话聊天历史；
   - 不依赖旧 Gemini 账号或 Google Drive（Google Drive 仅用于已完成正式个人小说的研发外备份）；
   - 不把当前临时 VM 当作唯一权威存储（当前主流程必需产物必须落盘并提交至 `chindden/chinese-novelist-skill`）。
5. **公私边界**：研发代码、文档与测试小说/实验评估原则上属公开研发资产（测试小说许可证状态为 `REVIEW`，不擅自选定许可证）；作者正式个人创作小说及其草稿/设定属私人资产，严禁入公开仓。

## 四、三方研发权限与分权机制

| 角色 | 职责与权限 | 硬红线 |
|---|---|---|
| **Neon（研发执行 Agent）** | 研发、实现、自测、撰写审计/实验报告、提交独立 Commit 与完整证据、维护上下文与进度日志 | **严禁自行将任何任务标记为 `ACCEPTED`**（最高可置为 `READY_FOR_REVIEW`）；严禁擅自修改冻结架构或越权启动未授权阶段 |
| **GPT-6（独立审核与知识治理）** | 独立审阅代码/文档/实验证据、提出整改项（`CHANGES_REQUESTED`）、确认验收通过（`ACCEPTED`）、阶段里程碑上下文一致性把关 | 不直接替代作者批准产品方向或重大范围变更 |
| **作者（最终决策者）** | 确立产品原则与研发目标、批准重大架构/范围变更、授予阶段启动权限（含本次预授权：文档过审后直接启动 `P0-0`） | 保留最终拍板权 |

## 五、标准任务交接格式（每次交接必填模板）

任何 Agent 在会话结束、阶段提交或移交工作时，必须输出以下 8 项结构化交接块：

```markdown
### Agent Handoff Summary
- **当前分支与 HEAD**：`<branch>` @ `<40-char SHA>`（`<UTC timestamp>`）
- **已完成任务**：<列出已获 ACCEPTED 或已提交的条目与 Commit SHA>
- **当前进行中的任务**：<唯一在研任务编号、状态及完成度>
- **尚未解决的问题**：<仅列影响当前主流程的真实阻塞/风险，注明是否阻断>
- **关键证据路径**：<仓库相对路径或 Commit 链接>
- **最近一次验收结果**：<GPT-6 结论 ACCEPTED / CHANGES_REQUESTED + 基线 SHA>
- **下一步唯一优先任务**：<明确且单一的下一步动作>
- **是否需要作者批准**：<是（列具体待批项）/ 否（说明已有授权依据）>
```

## 六、新 Agent 独立接管测试清单（轻量模拟验收）

不需要构建复杂自动化系统。验证接管机制有效时，向一个**未提供任何旧聊天记录、未挂载旧 Google Drive 账号**的全新 Agent 仅提供公开仓库 `chindden/chinese-novelist-skill` 与目标分支，按以下清单逐项打勾验收：

- [ ] **H-01 仓库与 HEAD 核对**：准确报出当前分支名、最新 40 位 HEAD SHA 及工作区是否干净，未把历史文档中的旧 SHA 当作实时 HEAD。
- [ ] **H-02 架构与边界复述**：准确区分“已冻结架构（`v1.2.3`）”“已验收管理 PRD（`v1.0.1`）”“已实现能力”与“设计/待验证能力”，未把 A/B/C、L0 或 5 分钟目标说成已实现。
- [ ] **H-03 资产与公私原则**：准确说明“主仓唯一、不建第二仓、按当前任务依赖保全、不强追全量历史考古、测试小说属公开研发资产且许可证 `REVIEW`、Drive 仅存正式完本个人小说”。
- [ ] **H-04 P0 实时状态与权限**：准确报出 `P0-0` ~ `P0-6` 实时状态、`G2-B = underpowered`，准确识别 Neon 最高 `READY_FOR_REVIEW`、`ACCEPTED` 仅归 GPT-6。
- [ ] **H-05 下一步动作判定**：能按第五节模板输出完整交接摘要，准确指出下一步唯一优先任务，且不越权修改代码、不把无关历史文件缺失误报为阻塞。
