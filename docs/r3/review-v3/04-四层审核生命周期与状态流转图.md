# 04 · 四层审核生命周期与状态流转图

> **文档版本**：`v1.2.2 (Freeze-Ready Final Candidate)`  
> **层级定位铁律**：  
> - **L0 全书机械诊断引擎（`diagnose_book.mjs`）与 `audit_story_state.mjs --readonly`** 是**贯穿整个创作周期的纯只读监测层（Continuous Read-Only Monitoring Layer）**，**不是**第五个强制文学审核关卡；二者均只输出 stdout，须分别通过全量静态审计 + 只读环境实际运行（首选只读 bind mount / Docker `:ro` 卷；采用 `chmod` 时须以独立非特权、非文件所有者 UID 运行且临时路径外置）+ 全目录 Manifest/SHA-256 比对三重验证，任一项未通过均不得宣称零写入；**`r3_ops.mjs` 是唯一允许承接诊断缓存写入的编排层，绝不因此放宽 L0 自身的只读要求**。  
> - **严格区分两类阻断态**：`FACT_CONFLICT_CANDIDATE` 进入**等待核实的临时安全门**（可核实误报/合法叙事后解除）；`STALE_REVIEW_AFTER_EDIT` 属于**工程完整性破损（`integrity_alert`）**，进入**工程完整性硬阻断态**（绝不允许标误报解除，必须显式 `retcon`/回滚 + 重审 + 更新指纹）。  
> - **L1–L4** 才是**四层文学质量审核流程**：L1（单章审核）→ L2（故事弧审核）→ L3（卷级文学审核与跨章修复）→ L4（完本全书终审与定向精修，**可选 Opt-in 功能，由作者决定是否启动，与独立的 5 分钟系统级性能优化路线 `Perf-Track` 彻底解耦**）。  
> **诚实声明**：本文各层耗时与摊销数据中，凡未实跑验证者均明确标注 **`[理论估算]`**，绝不冒充实测值；混合情景的理论 P50 在缺乏情景内经验分布时不凭权重与区间插值估算。

## 一、L0 只读监测层 × L1–L4 四层文学审核定位总表

| 层次与定位 | 触发频率 | 强制/可选 | 核心职责 | 是否新增 Agent 调用 | 成本边界与核算口径 |
|---|---|---|---|---|---|

| **L2 · 故事弧审核**（四层审核第 2 层） | **第 3 章（Pilot 停审）** + **第 6、9、12…章（3 章连续通读弧审）** | **强制** | 保留冷启动连续 3 章通读护城河：承诺兑现、冲突升级是否换皮、人物主动性、情绪喘息与余波、清偿 `fix_in_arc`（B 类）延期项；消费 L0 普通机械告警作为背景线索 | **不新增**（复用现有 Pilot / Arc 独立冷启动编辑） | 已有基线成本，单章摊销约 `1.8–2.5 m/章` `[历史记录重建/理论估算]` |

## 二、异常分级状态机边界与 L0 绝对零写入规范

### 1. 四类异常严格分流表（彻底分离 `FACT_CONFLICT_CANDIDATE` 与 `STALE_REVIEW_AFTER_EDIT`）

| 异常类别 | L0 / 状态枚举 | 典型触发条件 | 状态机路径与阻断性质 | 唯一合法恢复条件 |
|---|---|---|---|---|
| **类别 I · 普通机械告警与趋势线索** | `advise` / `note` | 某配角连续 4 章未出场、口头禅频次低、字数偏离参考值、对话占比波动、长句占比微升、高频短语、普通伏笔未推进、跨段排查后引号/重复段落候选、`STALE_CONTEXT_VERIFY` | **永不阻断当章推进**；透传至紧邻的下一次 L2 弧审或 L3 卷审作背景参考 | 无需强制恢复（编辑与作者结合语境自由判断） |
| **类别 II-A · 高危事实冲突候选（`FACT_CONFLICT_CANDIDATE`）** | `high_risk_fact_alert` | 同主体同键客观事实互斥候选（如角色状态/物品归属冲突候选）、结构化整数守恒失配候选 | **进入等待核实的临时安全门（`TempSafetyGate`）**，暂停开启第 $N+1$ 章直至核实（**非自动文学判决，绝不等到下一次 L2 弧审**） | ① 经独立核实/作者确认属**误报或合法叙事**（如不可靠叙事/刻意伏笔）→ **解除安全门直接放行，不改正文**；<br>② 核实为**真实错误** → 路由至当章定向修复或 `PLANNING_CONFLICT_BLOCK` |
| **类别 II-B · 工程完整性破损（含 `STALE_REVIEW_AFTER_EDIT`）** | `integrity_alert` | **已定稿正文未经显式 `retcon` 被外部修改（`STALE_REVIEW_AFTER_EDIT`）**；章节文件缺失/空文件、章号断档重复、JSON 语法损坏、伏笔 `payoffChapter < chapter` 倒挂 | **进入工程完整性硬阻断态（`IntegrityHardBlock`）**，**立即阻断一切新章写入**（与 `TempSafetyGate` 物理分离！） | **严禁仅通过标记“误报”或“合法叙事”直接解除！**<br>对 `STALE_REVIEW_AFTER_EDIT` 必须完成三步恢复：① 补走显式 `retcon` 审批与快照留痕（或回滚至原已定稿快照）；② 对改动章及 `analyze_impact.mjs` 直接影响集完成重新审核；③ 更新复合审读指纹 `reviewFingerprint` 与 `manuscriptHashes` 至最新有效状态 |
| **类别 III · 卷级宏观文学问题** | L3 卷审发现项 | 整卷主线承诺未兑现、核心人物跨卷弧光断裂、多章连续节奏疲软/文风系统性漂移、延期台账 `defer_to_final` 积压、卷末高潮兑现不足 | 归口 **L3 卷级文学审核** 集中定位与定性（卷末触发） | 卷审先读卷摘要 + L0 汇总并定点抽读 2–3 章证伪；如需回改历史已定稿章，必须经作者审批 + 快照 + `retcon` |

### 2. 彻底隔离 L0 只读脚本与编排层写入权限

为从代码级与运行期双重杜绝 L0 只读原则与任何磁盘写入产生冲突，执行**脚本级物理读写分离 + 三重零写入验收（任一项未通过均不得宣称零写入）**：

| 执行动作 | 所属层次 | 是否具备写盘能力 | 具体约束与验收方式 |
|---|---|---|---|
| `diagnose_book.mjs <proj> [--upto N] [--format json|md]` | **L0 只读监测层** | **否（代码级零写入，仅输出 stdout）** | 严禁调用任何直接/间接文件写入 API 或子进程写操作，不提供写路径参数；**独立接受三重验收**：① 全量静态审计；② 只读环境实测（**首选内核级只读挂载 `mount -o ro,bind` / Docker `:ro` 卷**；采用 `chmod -R a-w` 时**必须使用独立非特权、非文件所有者 UID 运行**，且所有测试临时文件/缓存置于项目目录之外）；③ 运行前后全项目 Manifest/SHA-256 比对 |
| 每 5 章滚动账本核查：`audit_story_state.mjs --upto N --readonly` | **L0 只读监测层** | **否（严格只读，禁用 `--write`）** | 仅向 stdout 输出事实冲突候选与完整性异常；**与 `diagnose_book.mjs` 分别独立接受上述全部三重零写入验收** |
| 派生缓存落盘与里程碑归档：`r3_ops.mjs`（`close-chapter` / `record-milestone`） | **编排事务层（非 L0）** | **是（唯一允许承接诊断缓存写入的编排层）** | ① 仅由 `r3_ops.mjs` 在外部捕获 `diagnose_book.mjs` 的 stdout 后写入隔离派生路径 `reviews/r3/diagnostics/.cache/book-diagnostics-latest.json`（可随时删除，不入故事真源哈希），**绝不因此放宽 L0 自身的只读要求**；<br>② 里程碑报告归档至 `reviews/r3/milestones/` |

## 三、全生命周期状态流转图（L0 纯只读监测贯穿 + L1–L4 四层审核）

```mermaid

    [*] --> Stage2_Planning: 核心契约双独审 + 卷一批准

    state "L1 · 单章创作与审核闭环（强制）" as L1 {
        [*] --> Drafting: start-chapter (纯叙事任务卡, 零治理词, 无限时压迫)
        Drafting --> Precheck: submit-draft (precheck v2)
        Precheck --> Drafting: 仅文件损坏或作者显式硬约束触发确定性阻断 (不空增revision)

        SemanticReview --> PlanningBlock: 命中上游/定稿死锁 (PLANNING_CONFLICT_BLOCK)
        SemanticReview --> Revise: 存在未决 draft_only BLOCKER/MAJOR (生成纯叙事修订卡)
        SemanticReview --> ChapterClosed: 0 阻断 (MINOR/SUGGESTION 不阻断)
        PlanningBlock --> SemanticReview: 作者批准修订规划或显式retcon后重审
        Revise --> Precheck: 写手按改动映射定向修复 (≤3轮; 第3轮不收敛→瓶颈诊断停交作者)
    }

    Stage2_Planning --> L1

    L1 --> CloseAndMonitor: close-chapter (增量合并账本/摘要) + L0 只读监测 (纯stdout 0写入, <0.5s)

    state "分轨门禁分流闸（严格分离工程硬阻断与临时安全门）" as Triage {
        CheckAlerts --> IntegrityHardBlock: 类别 II-B integrity_alert (含 STALE_REVIEW_AFTER_EDIT)
        CheckAlerts --> TempSafetyGate: 类别 II-A high_risk_fact_alert (FACT_CONFLICT_CANDIDATE)
        CheckAlerts --> MilestoneRouter: 仅类别 I 普通告警或无告警 (零阻断透传)
        IntegrityHardBlock --> RetconAndReReview: 严禁标误报解除! 必须显式retcon(或回滚)+重审+更新指纹
        RetconAndReReview --> MilestoneRouter: 完整性与最新指纹恢复有效
        TempSafetyGate --> MilestoneRouter: 核实为误报或合法叙事 → 解除安全门直接放行
        TempSafetyGate --> L1: 核实为真实事实错误 → 当章定向修复或 PLANNING_CONFLICT_BLOCK
    }

    CloseAndMonitor --> Triage

    state "L2 · 故事弧审核（强制，消费 L0 普通线索）" as L2 {
        MilestoneRouter --> PilotGate: 第 3 章
        MilestoneRouter --> ArcReview: 第 6, 9, 12... 章
        MilestoneRouter --> NextChapter: 常规章 (含第 5/10... 章无高危候选与完整性破损时直接放行)
        PilotGate --> AuthorPilotApprove: 独立冷启动3章连读通过
        AuthorPilotApprove --> NextChapter: 真实作者批准 (解封 Ch 4)
        ArcReview --> NextChapter: 独立冷启动3章通读 + 清偿 fix_in_arc + 审阅 L0 线索
    }

    L2 --> L1: 卷内下一章
    L2 --> L3_Vol: 抵达当前卷末章

    state "L3 · 卷级文学审核与跨章修复（卷末）" as L3_Vol {
        VolCand["脚本汇编: 卷摘要候选 + L0 全卷诊断 + 伏笔/延期盘点 (<1s)"] --> VolAudit["L3-A 正常卷审 (1次聚焦调用, 估算4-7m; 仅读摘要+异常+抽审2-3章)"]
        VolAudit --> VolRepair["L3-B 发现跨章问题后的修复与复审 (成本单列; 历史回改须作者批准+retcon)"]

    L3_Vol --> L1: 开启下一卷 (卷摘要进入下卷首章衔接)
    L3_Vol --> L4_Final: 全书终卷完成 (仅当启用成书完本精修模式)

        FinalPolish --> FinalDelivery["L0 全书只读终检 + r3_delivery 完整交付包"]
    }

    L4_Final --> [*]
```

## 四、六个关键生命周期架构问题解答

### 问题 1：如何保留现有前三章 Pilot 和每 3 章连续通读审核？
- **原样保留护城河**：第 3 章 Pilot 停审与第 6/9/12…章三章弧审在底层门禁 `v3_gate.mjs` 中**原样保留**。
- **两项无损提效改造**：
  1. **禁止顺带修改已通过章的 `MINOR/SUGGESTION`**：Pilot/弧审仅对存在 `BLOCKER/MAJOR` 的章节触发返工（避免重演 Step 3 因顺带修 Ch 1 两条 MINOR 而引发 `11.5 min` 级联冷重审）；
  2. **注入 L0 只读机械诊断背景摘要**：冷启动弧审编辑开读前先收到 ≤15 行近窗客观统计线索（对话占比、长句密度、人物出场表、高频短语），将注意力留给节奏、承诺兑现与文学质感。

### 问题 2：如何让每 5 章账本核查、L2 故事弧审核与 L3 卷审协同而不重复、不漏高危？
- **每 3 章（L2 弧审：Ch 6, 9, 12…）**：独立冷启动 3 章通读，负责文学张力、局部承诺兑现、反换皮与清偿 `fix_in_arc`。
- **每 5 章（L0 纯只读滚动核查：Ch 5, 10, 15…）**：仅执行纯只读脚本（`audit_story_state.mjs --readonly` + `diagnose_book.mjs`，`<0.5s`，零磁盘写入、零常驻 LLM 编辑）——
  - 命中 **类别 II-B 工程完整性破损**（含 `STALE_REVIEW_AFTER_EDIT`）→ 立即进入**工程完整性硬阻断态**（不可标误报解除，必须显式 `retcon`/回滚 + 重审 + 更新指纹）；
  - 命中 **类别 II-A 高危事实候选**（`FACT_CONFLICT_CANDIDATE`）→ 立即拉起**等待核实的临时安全门**，暂停开启第 $N+1$ 章直至核实（误报/合法叙事可解除，真错转修复，绝不拖到下一次 L2 弧审）；
  - 仅命中 **类别 I 普通告警** → 零阻断，摘要并入下一次 3 章弧审，彻底消除重复独立编辑。
- **每卷末（L3 卷审）**：负责整卷级宏观文学闭环、权威卷摘要定稿与跨章修复。

### 问题 3：卷末应检查什么？正常卷审与发现问题后修复成本如何分开核算？
- **卷末 5 项检查**：① 卷纲兑现与偏离对账；② 跨章人物与关系弧光（结合 L0 在场矩阵）；③ 全卷伏笔与延期台账结账；④ 全卷机械诊断趋势审计；⑤ 产出 ≤600 字权威 `volume-NN-summary.md`。
- **跨章问题定位三步漏斗**（严禁塞整卷全文）：确定性脚本漏斗 → 摘要级宏观扫查（20 章 × 200 字 ≈ 4,000 字）→ 定点抽读 2–3 章相关段落证伪。
- **成本两笔账分算（`[理论估算]`，严禁将修复成本藏进 `<0.3 min/章` 均摊）**：
  - **L3-A 正常卷审（0 历史回改）**：脚本 `<1s` + 1 次聚焦卷审估算 `4–7 min/卷`（20 章摊销 `0.20–0.35 min/章`）；
  - **L3-B 发现问题后的修复与复审**：
    - 轻度（仅调整卷摘要/下卷钩子，0 正文改动）：`+1–3 min/卷`；
    - 中度（需回改 1–2 个已定稿章局部事实）：快照+影响分析 (`<1s`) + 写手定向改稿 (`2–4m/章`) + 本章及直接下游影响章回归复审 (`3–7m/章`)，合计估算 **`+10–25 min/卷`**（20 章摊销 `+0.50–1.25 min/章`）；
    - 重度（跨 3+ 章结构性回改）：合计估算 **`+30–60+ min/卷`**，强制向作者呈报影响集与代价估算，由作者抉择“回改历史 vs 下卷显式 `retcon`/剧情补偿”。

### 问题 4：完本审核如何避免一次性将全书塞入模型上下文？
采用**金字塔四层索引 + 定点原文取证**（详见 L4 状态机）：Layer 1 全书核心契约 + 各卷摘要（~3–6 千字）→ Layer 2 脚本汇编三总表（人物弧线总表 + 伏笔总账 + `defer_to_final` 台账与 L0 全书汇总，~4–8 千字）→ Layer 3 仅按异常点分批抽读 2–4 章原文切片（≤1.5 万字/批，必抽开篇与终局）→ Layer 4 精修前全书快照 + 分章定向精修 + 影响集回归复核。

### 问题 5：哪些问题可自动修复，哪些必须经过作者批准？
- **可自动处理（无需打扰作者）**：纯工程缓存/格式整理、未定稿单章内 `draft_only` 的 `BLOCKER/MAJOR`（写手定向修复 + 复审，上限 3 轮；第 3 轮不收敛则提交瓶颈诊断交作者）。
- **不自动触发返工**：单章局部 `MINOR` / `SUGGESTION`、L0 普通机械告警（重复段落候选、引号提醒、字数波动等）。
- **必须经真实作者明确批准**：`PLANNING_CONFLICT_BLOCK`（上游规划/设定修改）、已定稿历史章节回改与 `retcon` 补偿、Pilot 停审放行、核心契约/卷级审批、L4 完本精修范围确认。

### 问题 6：修改一个章节后，如何识别需要重新审核的下游章节？
由纯只读脚本 `analyze_impact.mjs`（`<0.3s`）执行三级判定：
1. **L0 级微修**（纯措辞/标点，零事实/状态/时间/物品/知情变更）→ `downstreamChapters = []`（零级联）；
2. **直接依赖集（Hard Impact Set）**→ 相邻衔接章 $k+1$（`check_seam`）+ `story-ledger.json` 中引用第 $k$ 章建立/变更事实、伏笔、关系的下游章 + 所属 3 章弧与卷摘要标 `stale`；
3. **实体共现候选集（Candidate Impact Set，非强制重审）**→ 利用 L0 实体索引列出下游高频共现章及行号，交由编辑/作者判断抽审，杜绝全书雪崩重审。
