# 04 · 四层审核生命周期与状态流转图

> **文档版本**：`v1.1 (Freeze-Ready Candidate)`  
> **层级定位铁律**：  
> - **L0 全书机械诊断引擎**是**贯穿整个创作周期的只读监测层（Continuous Read-Only Monitoring Layer）**，**不是**第五个强制文学审核关卡，默认对磁盘零写入，永不凭统计异常自动阻断文学通过。  
> - **L1–L4** 才是**四层文学质量审核流程**：L1（单章审核）→ L2（故事弧审核）→ L3（卷级文学审核与跨章修复）→ L4（完本全书终审与定向精修，P2 可选）。  
> **诚实声明**：本文各层耗时与摊销数据中，凡未实跑验证者均明确标注 **`[理论估算]`**，绝不冒充实测值。

## 二、异常分级触发边界与 L0 只读防冲突规范

### 1. 三类异常严格分流表（高危事实冲突绝不等到下一次 L2 故事弧审核！）

| 异常类别 | 典型情形 | 触发时机与阻断边界 | 处置路径 |
|---|---|---|---|
| **类别 I · 普通机械告警与趋势线索** | 某配角连续 4 章未出场、口头禅频次低、字数高于/低于参考值、对话占比波动、长句占比微升、高频短语、未超硬死线的普通伏笔未推进、跨段排查后的疑似引号/重复段落候选 | **永不阻断当章推进**；随 L0 只读诊断快照附入紧邻的下一次 **L2 故事弧审核**（Ch 6/9/12…）或 **L3 卷审** 作背景参考 | 编辑与作者结合语境自由判断是否采纳，不自动触发返工 |
| **类别 II · 高危事实冲突与工程状态破损** | `FACT_CONFLICT_CANDIDATE`（同主体同键客观事实互斥，如已死人物出场/账面余额变负/核心时间倒挂）、结构化整数守恒失配、`STALE_REVIEW_AFTER_EDIT`（审后正文被外部未走 `retcon` 修改）、单章发现 `impactScope = upstream_planning / finalized_canon` | **严禁拖到下一次 L2 故事弧审核！必须在发现当章立刻拦截（Immediate Triage，阻断开启第 $N+1$ 章）** | ① 属当章笔误 → 立即启动当章定向局部复核与修订；<br>② 属上游规划/已定稿历史冲突 → 立即挂起并输出 `PLANNING_CONFLICT_BLOCK` + `analyze_impact.mjs` 影响报告呈交作者裁决 |
| **类别 III · 卷级宏观文学问题** | 整卷主线承诺未兑现、核心人物跨卷弧光断裂、多章连续节奏疲软/文风系统性漂移、延期台账 `defer_to_final` 积压、卷末高潮兑现不足 | 归口 **L3 卷级文学审核** 集中定位与定性（卷末触发） | 卷审先读卷摘要 + L0 汇总，仅定点抽读 2–3 章原文证伪；如需回改历史已定稿章，必须经作者审批 + 快照 + `retcon` |

### 2. 彻底解决“每 5 章脚本运行是否产生写入”与 L0 只读原则的冲突

为消除“一边宣称 L0 100% 只读、一边在每 5 章跑 `audit_story_state.mjs --write`”的架构自相矛盾，明确切分**只读监测层（L0）**与**事务编排层（`r3_ops.mjs`）**的写权限边界：

| 执行动作 | 所属层次 | 是否产生磁盘写入 | 具体约束 |
|---|---|---|---|
| `diagnose_book.mjs <proj> [--upto N]` | **L0 只读监测层** | **否（默认 0 字节写入，纯 stdout JSON/MD）** | 绝不写正文、大纲、计划、账本或摘要；仅当编排层显式传 `--cache-file reviews/r3/diagnostics/.cache/book-diagnostics-latest.json` 时才写受隔离、可随时删除的派生缓存 |
| 每 5 章滚动账本核查：`audit_story_state.mjs --upto N --readonly` | **L0 只读监测层** | **否（严格只读，禁用 `--write`）** | 仅检测 `FACT_CONFLICT_CANDIDATE`、整数守恒失配与伏笔倒挂：<br>① 若检出 **类别 II 高危事实冲突** → 立刻阻断第 $N+1$ 章进入即时处置；<br>② 若仅检出 **类别 I 普通告警** → 零阻断，摘要带入下一次 L2 弧审 |
| 里程碑报告归档：`r3_ops.mjs record-milestone` / `close-chapter` | **编排事务层（非 L0）** | **是（仅写审计日志与显式事务文件）** | 仅在章节关闭或里程碑确认时将审计报告归档至 `reviews/r3/milestones/`，或按作者/写手确认的增量块更新账本，**与 L0 只读监测职责物理隔离** |

    state "L1 · 单章创作与审核闭环（强制）" as L1 {

## 四、六个关键生命周期架构问题解答

### 问题 1：如何保留现有前三章 Pilot 和每 3 章连续通读审核？
- **原样保留护城河**：第 3 章 Pilot 停审与第 6/9/12…章三章弧审在底层门禁 `v3_gate.mjs` 中**原样保留**。
- **两项无损提效改造**：
  1. **禁止顺带修改已通过章的 `MINOR/SUGGESTION`**：Pilot/弧审仅对存在 `BLOCKER/MAJOR` 的章节触发返工（避免重演 Step 3 因顺带修 Ch 1 两条 MINOR 而引发 `11.5 min` 级联冷重审）；
  2. **注入 L0 只读机械诊断背景摘要**：冷启动弧审编辑开读前先收到 ≤15 行近窗客观统计线索（对话占比、长句密度、人物出场表、高频短语），将注意力留给节奏、承诺兑现与文学质感。

### 问题 2：如何让每 5 章账本核查、L2 故事弧审核与 L3 卷审协同而不重复、不漏高危？
- **每 3 章（L2 弧审：Ch 6, 9, 12…）**：独立冷启动 3 章通读，负责文学张力、局部承诺兑现、反换皮与清偿 `fix_in_arc`。
- **每 5 章（L0 只读滚动核查：Ch 5, 10, 15…）**：仅执行纯只读脚本（`audit_story_state.mjs --readonly` + `diagnose_book.mjs`，`<0.5s`，零磁盘写入、零常驻 LLM 编辑）——
  - 发现 **类别 II 高危事实冲突** → **当章立即阻断并即时处理**，绝不拖延到下一弧审；
  - 仅发现 **类别 I 普通告警** → 零阻断，随诊断摘要并入下一次 3 章弧审，彻底消除重复独立编辑。
- **每卷末（L3 卷审）**：负责整卷级宏观文学闭环、权威卷摘要定稿与跨章修复。

### 问题 3：卷末应检查什么？正常卷审与发现问题后修复成本如何分开核算？
- **卷末 5 项检查**：① 卷纲兑现与偏离对账；② 跨章人物与关系弧光（结合 L0 在场矩阵）；③ 全卷伏笔与延期台账结账；④ 全卷机械诊断趋势审计；⑤ 产出 ≤600 字权威 `volume-NN-summary.md`。
- **跨章问题定位三步漏斗**（严禁塞整卷全文）：确定性脚本漏斗 → 摘要级宏观扫查（20 章 × 200 字 ≈ 4,000 字）→ 定点抽读 2–3 章相关段落证伪。
- **成本两笔账分算（`[理论估算]`，严禁将修复成本藏进 `<0.3 min/章` 均摊）**：
  - **L3-A 正常卷审（0 历史回改）**：脚本 `<1s` + 1 次聚焦卷审估算 `4–7 min/卷`（20 章摊销 `0.20–0.35 min/章`）；
  - **L3-B 发现问题后的修复与复审**：
    - 轻度（仅调整卷摘要/下卷钩子，0 正文改动）：`+1–3 min/卷`；
    - 中度（需回改 1–2 个已定稿章局部事实）：快照+影响分析 (`<1s`) + 写手定向改稿 (`2–4m/章`) + 本章及直接下游影响章回归复审 (`3–7m/章`)，合计估算 **`+10–25 min/卷`**（20 章摊销 `+0.50–1.25 min/章`）；
    - 重度（跨 3+ 章结构性回改）：合计估算 **`+30–60+ min/卷`**，强制向作者呈报影响集与代价估算，由作者抉择“回改历史 vs 下卷显式 `retcon`/剧情补偿”。

### 问题 4：完本审核如何避免一次性将全书塞入模型上下文？
采用**金字塔四层索引 + 定点原文取证**（详见 L4 状态机）：Layer 1 全书核心契约 + 各卷摘要（~3–6 千字）→ Layer 2 脚本汇编三总表（人物弧线总表 + 伏笔总账 + `defer_to_final` 台账与 L0 全书汇总，~4–8 千字）→ Layer 3 仅按异常点分批抽读 2–4 章原文切片（≤1.5 万字/批，必抽开篇与终局）→ Layer 4 精修前全书快照 + 分章定向精修 + 影响集回归复核。

### 问题 5：哪些问题可自动修复，哪些必须经过作者批准？
- **可自动处理（无需打扰作者）**：纯工程缓存/格式整理、未定稿单章内 `draft_only` 的 `BLOCKER/MAJOR`（写手定向修复 + 复审，上限 3 轮；第 3 轮不收敛则提交瓶颈诊断交作者）。
- **不自动触发返工**：单章局部 `MINOR` / `SUGGESTION`、L0 普通机械告警（重复段落候选、引号提醒、字数波动等）。
- **必须经真实作者明确批准**：`PLANNING_CONFLICT_BLOCK`（上游规划/设定修改）、已定稿历史章节回改与 `retcon` 补偿、Pilot 停审放行、核心契约/卷级审批、L4 完本精修范围确认。

### 问题 6：修改一个章节后，如何识别需要重新审核的下游章节？
由纯只读脚本 `analyze_impact.mjs`（`<0.3s`）执行三级判定：
1. **L0 级微修**（纯措辞/标点，零事实/状态/时间/物品/知情变更）→ `downstreamChapters = []`（零级联）；
2. **直接依赖集（Hard Impact Set）**→ 相邻衔接章 $k+1$（`check_seam`）+ `story-ledger.json` 中引用第 $k$ 章建立/变更事实、伏笔、关系的下游章 + 所属 3 章弧与卷摘要标 `stale`；
3. **实体共现候选集（Candidate Impact Set，非强制重审）**→ 利用 L0 实体索引列出下游高频共现章及行号，交由编辑/作者判断抽审，杜绝全书雪崩重审。
