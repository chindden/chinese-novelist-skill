## 二、核心结论摘要（v1.1 冻结候选口径）

### 1. R3 当前最应该先解决的三个问题
1. **以实证对照破解审稿“发现 vs 克制”跷跷板与 `OR6` 漂白漏洞**：v2.2 已暴露单轮调参瓶颈（FPR `15.15% > 15.0%`、跨题材 `V22-H3` 漏检、`V22-H4` 漂白 BLOCKER）。v3 通过 `precheck v2`（`NEEDS_SEMANTIC_AUDIT`）、6 维最小取证槽与 `PLANNING_CONFLICT_BLOCK` 筑底，并在 P0-6 执行 **A（单阶段完整）vs B（Pass 1 发现 + Pass 2 定级）vs C（单阶段 + 独立轻量定级）** 三方案离线对照，**不预设双阶段必胜**，由大样本 G1–G6 数据决定胜出架构。
2. **彻底隔离创作层与治理层语域（写手语域防火墙）**：写手上下文零 SHA/JSON/门禁码/`reverseDefense`/限时压迫词，动笔前最后读段强制为“上章结尾 + 文风示范”，返工仅投喂纯叙事修订卡 + `preserveStrengths`，从源头治本报告腔与防杠说明书补丁。
3. **重塑单章端到端时间账本，务实推进 5 分钟生产系统北极星目标**：将 `17–22m`（历史重建）与 `24–31m`（实时日志）分开校准口径；不提前放弃 5 分钟目标（明确其为系统架构目标而非写手限时指令），先在 P0/P1 通过调用合并、热复用、尺度校准降无效返工、增量脚本合并收尾把实测 P50 压向 `<= 13.0m`（热）/ `<= 16.5m`（冷）`[理论估算待实测]`，再在 P2 通过收尾异步化、审稿维度并行化与辅助低延迟路由向 `<= 5.0–7.0m` 冲刺。

### 2. 立即补齐（P0）vs 紧随其后（P1）vs 暂缓（P2）vs 明确不做
- **立即补齐（P0）**：S1 四级枚举兼容与 `ENG-FIX-P1`、写手语域防火墙、`precheck v2`（仅文件破损与作者显式硬约束阻断 + `NEEDS_SEMANTIC_AUDIT`）、复合审读指纹 + Fail-Closed + 修空增版本 Bug、三方案审稿原型（A/B/C）+ `PLANNING_CONFLICT_BLOCK` 及其 **P0-6 大样本离线对照（过升级版 G1–G6 才准入主仓）**。
- **紧随其后（P1）**：L0 全书只读机械诊断引擎（`diagnose_book.mjs`，9 维 `D1–D9`，默认 0 写入、非第五道审核关卡）、三元组跨轮继承 + 改动映射 + 3 轮瓶颈诊断、统一 CLI `r3_ops.mjs` + 增量账本合并收尾、`analyze_impact.mjs` + 显式 `retcon`、L2（每 5 章只读核查+高危当章即时阻断）与 L3 卷审工作流（正常卷审与修复成本分算）、跨 Harness 适配层分离。
- **暂缓（P2）**：L4 完本全书终审与定向精修（可选成书模式）、5 分钟北极星架构冲刺实验（收尾异步化 M-D / 并行分维审稿 M-E / 辅助路由 M-F / `risk_tiered` / 10–26 章跨卷验证）。
- **明确不做**：每章强制独立润色/沉淀子代理、`MINOR/SUGGESTION` 强制人工处置、修完不复审、重型向量库主路径、总分扣分制、P0/P1 本地 Web 书房服务器、把 5 分钟变成写手限时或为字数牺牲内容完整性。

### 3. 四条独立反对意见（反方压测摘要）
1. **双阶段审稿（方案 B）不必然稳赢**：若 Pass 1 漏检，Pass 2 不读全章无法补救；必须与方案 A/C 同台跑大样本离线对照并用 6 维取证槽 + `NEEDS_SEMANTIC_AUDIT` 兜底。
2. **严防四层审核 + L0 演变为官僚机器**：L0 锁定为 0 写入只读监测层且永不阻断，L4 锁定为 P2 Opt-in，L2 取消重复的每 5 章常驻编辑（仅高危冲突即时阻断）。
3. **严防三元组跨轮继承在半自动模式下沦为放行后门**：仅允许继承**真实作者明确批注**且**原段落哈希未变**的条目。
4. **严防 5 分钟目标异化为对写手施压或降质借口**：5 分钟只能靠系统架构与编排优化争取，任何提速必须先过 Track L 盲评与零漏检恶化门禁。
