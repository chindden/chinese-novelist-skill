## 二、核心结论摘要（v1.2 冻结候选口径）

### 1. R3 当前最应该先解决的三个问题
1. **以实证对照破解审稿“发现 vs 克制”跷跷板与 `OR6` 漂白漏洞**：在 `precheck v2`（`NEEDS_SEMANTIC_AUDIT`）、6 维最小取证槽与 `PLANNING_CONFLICT_BLOCK` 共同底座上，P0-6 执行 **A（单阶段完整）vs B（Pass 1 发现 + Pass 2 定级）vs C（单阶段 + 独立轻量定级）** 三方案离线对照，**不预设双阶段必胜**，由严格处理样本聚类与加权一致性的 G1–G6 准入规则裁决胜出架构。
2. **彻底隔离创作层与治理层语域（写手语域防火墙）**：写手上下文零 SHA/JSON/门禁码/`reverseDefense`/限时压迫词，动笔前最后读段强制为“上章结尾 + 文风示范”，返工仅投喂纯叙事修订卡 + `preserveStrengths`，从源头治本报告腔与防杠说明书补丁。
3. **建立算术闭合的时间账本，务实推进“含必要返工与复审在内的 5 分钟”全口径系统目标**：统一 Mean / P50 / P90 与严格互斥五阶段边界，明确 `17–22m`（历史重建）与 `24–31m`（实时日志）不可直比；P0+P1 阶段务实验收门槛锁定为热复用 **P50 `<= 13.5m` / Mean `<= 14.5m`**（全冷 **P50 `<= 16.5m` / Mean `<= 18.0m`**）`[理论估算待实测]`，再通过 P2 替代架构受控实验（注明重叠、禁止简单相加，M-A 列为待验证风险评估）与模型延迟演进向全样本（含必要返工与复审）`<= 5.0m` 收敛。

### 2. 立即补齐（P0）vs 紧随其后（P1）vs 暂缓（P2）vs 明确不做
- **立即补齐（P0）**：S1 四级枚举兼容与 `ENG-FIX-P1`、写手语域防火墙、`precheck v2`（仅文件破损与作者显式硬约束阻断 + `NEEDS_SEMANTIC_AUDIT`）、复合审读指纹 + Fail-Closed + 修空增版本 Bug、三方案审稿原型（A/B/C）+ `PLANNING_CONFLICT_BLOCK` 及其 **P0-6 大样本离线对照（过 G1–G6 准入规则才准入主仓）**。
- **紧随其后（P1）**：L0 全书只读机械诊断引擎（`diagnose_book.mjs`，9 维 `D1–D9`，**只读仅输出 stdout**，非第五道审核关卡）、三元组跨轮继承 + 改动映射 + 3 轮瓶颈诊断、统一 CLI `r3_ops.mjs`（单独承接诊断缓存落盘 + 增量账本合并收尾）、`analyze_impact.mjs` + 显式 `retcon`、L2（每 5 章只读核查 + 高危候选触发等待核实的临时安全门）与 L3 卷审工作流（正常卷审与修复成本分算）、跨 Harness 适配层分离。
- **暂缓（P2）**：L4 完本全书终审与定向精修（可选成书模式）、5 分钟全口径北极星架构冲刺实验（收尾异步化 M-D / 并行分维审稿 M-E / 辅助路由 M-F / `risk_tiered` / 10–26 章跨卷验证）。
- **明确不做**：每章强制独立润色/沉淀子代理、`MINOR/SUGGESTION` 强制人工处置、修完不复审、重型向量库主路径、总分扣分制、P0/P1 本地 Web 书房服务器、把 5 分钟变成写手限时或为字数牺牲内容完整性。

### 3. 文学验收无空白三带裁决摘要（详见 `08`）
多评委（≥2 独立冷启动评委 + 绝对一致性 `ICC(A,1)`/`ICC(2,1)` 主指标 + Spearman $\rho$ 辅指标 + 分差 `>=1.5` 触发第 3 仲裁评委）匿名盲评综合均分差 $\Delta S = \bar{S}_{\text{v3}} - \bar{S}_{\text{baseline}}$：
- **$\Delta S \ge -0.20$** → ✅ **PASS**；
- **$-0.30 \le \Delta S < -0.20$** → ⚠️ **CONDITIONAL / HOLD**（强制低分归因复核，若属机制性缺陷则回退，否则必须扩样 `+3` 章重评，合并后仍 `< -0.20` 强制回退）；
- **$\Delta S < -0.30$** → ❌ **FAIL / IMMEDIATE ROLLBACK**。
