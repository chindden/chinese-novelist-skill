## 二、明确“不采纳 / 不值得做”的能力清单（防过度工程红线）

为了避免审核系统反向拖垮创作效率与可读性，以下 7 项外部项目能力**明确不采纳**：

1. **❌ 不采纳 v8 的“每章强制独立润色子代理 + 独立沉淀对账子代理”**
   - **原因**：v8 面向桌面端慢节奏人机逐章协作；若在 R3 单章主路径固定再加 2 个串行子代理（`polish` + `settle`），将直接背离 5 分钟单章系统优化目标。替代方案：创作层语域防火墙 + 审后增量脚本收尾（并探索收尾异步化），仅在作者点名或高风险章按需启用独立润色/对账。
2. **❌ 不采纳 v8 的“所有 `建议`/`仅供参考` 条目均强制逐条手工处置后才算审核完成”**
   - **原因**：会把非阻断 `MINOR/SUGGESTION` 变相变成交互阻断负担，违背 Blind Audit C 与校准方案“保护创作流、非阻断不强迫立即闭环”的核心结论。
3. **❌ 不采纳 `webnovel-writer v6` 的“单轮审查、修完不复审”**
   - **原因**：Blind Audit A 与 Step 3 已实证返工回归率极高（Arm 2/3 4 次大改熔断中 3 次抓出真回归；Step 3 Ch1 v2/v4 两次修旧引新），修完不复审直接击穿质量底线。
4. **❌ 不采纳 `webnovel-writer v6` 的 5 路重型 Projection + 持久向量库主路径**
