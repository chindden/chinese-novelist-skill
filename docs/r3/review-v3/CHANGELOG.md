## `v1.2.3`（2026-11-25）—— 合并前唯一技术细节澄清：L0 Manifest 前后校验与只读运行环境统一

### 唯一修订 · L0 Manifest/SHA-256 与只读挂载环境同树一致（影响：`05`、`08`、`README`）
- **修订前（`v1.2.2`）**：`05` 4.2 节第三重校验写成“在可写副本中分别运行两个脚本前后，递归计算整个项目目录……”，与第二重“只读挂载运行”产生口径冲突。
- **修订后（`v1.2.3`）**：
  1. 被测项目目录通过只读 bind mount（`mount -o ro,bind`）或 Docker `:ro` 卷挂载给被测进程；
  2. `diagnose_book.mjs` 与 `audit_story_state.mjs --readonly` 分别直接在该只读挂载环境中执行；
  3. Manifest/SHA-256 由宿主机侧对**同一个底层项目目录**计算运行前后的结果；
  4. 明确保证运行前后哈希检查的对象与实际被测目录是**同一个底层文件树**，严禁用另一个可写副本代替；
  5. 如果额外使用可写副本进行补充测试，只能作为辅助测试，不能替代只读挂载验收；
  6. 对 `chmod -R a-w` 回退方案明确区分**权限准备阶段**与**被测程序运行阶段**：准备阶段设权后，被测程序必须以独立非特权、非文件所有者 UID 执行。

## `v1.2.2`（2026-11-25）—— 正式冻结前三项剩余问题定点闭环修订

### 1. G2 统计验收：彻底分离历史校准集与独立 Holdout（影响：`03`、`07`、`08`、`README`）
- **修订前（`v1.2.1`）**：G2 将历史 Track 2 的 `9` 章 / `33` 条非阻断案例与新增 `11–14` 章 / `27–40` 条新案例合并为单一 `>=20` 章 / `>=60` 条混合样本池，可能因规则在历史章节上过拟合而高估跨章节独立泛化能力。
- **修订后（`v1.2.2`）**：
  - **`G2-A · Regression / Calibration`（历史校准回归集）**：单独固定保留历史校准样本（`N_ch = 9`, `N_neg = 33`, `K = 3`），仅用于回归验证与规则稳定性检查；
  - **`G2-B · Independent Holdout`（全新独立非阻断盲测集）**：单独要求 `N_ch >= 20` 个**从未参与规则设计、调优或揭盲**的全新独立来源章节（与历史校准集及已揭盲旧 Holdout `0` 章重叠）、`N_neg >= 60`（单章 `<= 3` 条）、覆盖 `>= 3` 类题材、`K = 3`；
  - **严格分轨报告与硬红线**：两组**分别报告**原始 `TP / FP / FN / TN`、Precision、FPR 及章节级聚类 Bootstrap 95% CI，**严禁混合两组结果作为独立泛化证明**，明示“**历史校准集通过 ≠ 独立 Holdout 泛化通过**”；
  - **诚实标注 `underpowered` 状态**：明确标注当前 `G2-B` 为 **`underpowered`（当前就绪 `0` 章 / `0` 案例；距过线仍缺 `+20` 个全新独立来源章节、`+60` 条独立非阻断案例）**，绝不降低原有统计门槛或将样本不足包装为通过。

### 2. L0 零写入验证：补严只读沙箱权限边界（影响：`03`、`04`、`05`、`07`、`08`、`README`）
- **修订前（`v1.2.1`）**：允许用“等效非特权 `chmod -R a-w` 沙箱”替代只读挂载，但未明确指出文件所有者 UID 或 root 仍可通过 `chmod` 恢复写权限并绕过只读检查，也未明确隔离临时文件/缓存路径与“任一项失败即零写入不成立”。
- **修订后（`v1.2.2`）**：
  - **首选内核级只读挂载**：优先使用只读 bind mount（`mount -o ro,bind`）或容器/Docker `:ro` 只读卷挂载整座项目目录；
  - **`chmod -R a-w` 严格前置条件**：若受环境限制必须使用 `chmod -R a-w`，**必须在独立非特权、非文件所有者 UID 下执行**（文件所有者自身或 root 运行 `chmod -R a-w` 测试一律判无效）；
  - **临时路径外置与双脚本独立验收**：被测项目目录保持绝对只读，所有测试临时文件、日志、缓存与运行时目录均置于项目目录之外；对 **`diagnose_book.mjs`** 与 **`audit_story_state.mjs --readonly`** 分别独立执行三重验证；
  - **三重验证硬闭环**：保留“全量静态审计 + 只读环境实际运行 + 运行前后全目录 Manifest/SHA-256 比对”，明示静态扫描不等同于运行期零写入证明，**三项中任何一项未通过均不得宣称零写入成立**。

### 3. 路线图结构：5 分钟系统性能目标与可选 L4 彻底解耦（影响：`03`、`04`、`07`、`08`、`README`）
- **修订前（`v1.2.1`）**：将 5 分钟全口径架构实验（原 `P2-3`）与可选 L4 完本终审（`P2-1`/`P2-2`）混排在同一“暂缓（P2）”分组下，容易造成“因为 L4 是可选功能，所以 5 分钟优化也是可做可不做”的路线误解。
- **修订后（`v1.2.2`）**：
  - 将 P1 稳定后的工作拆分为两条**完全独立、互不隶属**的轨道：
    - **轨道 A · `Perf-Track`（5 分钟端到端独立系统性能轨道：`S1 → S2 [PERF-S2] → S3 [PERF-S3]`）**：独立、持续推进的系统级性能优化路线，P1 稳定后持续演进，**绝不因为 L4 可选而降级为可选目标**；
    - **轨道 B · `P2-OptIn`（L4 完本全书终审与定向精修：`P2-1 → P2-2`）**：由作者按需决定是否启用的成书模式可选功能，不影响 P0/P1 核心审核与 `Perf-Track`；
  - 重申四条硬底线：始终以含必要返工与复审的全样本实测 Mean 与经验 P50 评估；缺乏实跑日志前绝不宣称已实现或已验证；严禁向写手施加限时压迫；严禁通过缩减正文长度或跳过复审换取耗时下降。

## `v1.2.1`（2026-11-25）—— 独立复审四项定点闭环修订（P1–P4）

### 1. P1 · 修正 Mean / P50 混合情景模型（影响：`01`、`03`、`04`、`07`、`08`、`README`）
- **分别建立 Mean 与 P50 的数学计算方法**：在 `03` 3.5 节明确 **Mean** 严格由全期望公式 $E[T] = \sum w_i\mu_i$ 计算（仅依赖情景权重与条件均值，热复用假设下理论参考 `~12.9m` [`10.9–15.0m`] `[理论估算]`），而 **P50** 必须基于三个情景各自的分布函数求解混合 CDF 方程 $F_{\text{mix}}(t_{0.5}) = \sum w_i F_i(t_{0.5}) = 0.5$，绝不能仅凭情景权重和区间端点线性插值。
- **删除缺乏分布依据的理论 P50 数值**：彻底删除 v1.2 中 `热复用 P50 约 11.2–13.5 min`、`全冷 P50 约 13.5–16.5 min`、`一次通过率 50% 时 P50 下探至 ~10.9–11.5 min` 等插值估算；明确标注在取得实跑经验分布 $\hat{F}_i(t)$ 之前，**混合分布理论 P50 无法精确估算**。
- **明确“一次通过率达到 50% 不等于可直接推导 P50 具体数值”**：在 `03` 3.5 节与 `08` 给出分布形状/偏态与支撑重叠的数学说明。
- **区分理论估算与实跑经验验收红线**：在 `03`、`04`、`08` 明确 `08` 中的经验 P50（热复用 `<= 13.5m` / 全冷 `<= 16.5m`）是面向未来实跑经验分布设定的工程验收上限，而非权重插值推导值；全程保留 `[真实运行日志]` / `[历史记录重建]` / `[理论估算]` / `[无法测量]` 四级证据分层。

### 2. P2 · 统一 `STALE_REVIEW_AFTER_EDIT` 状态机（影响：`02`、`03`、`04`、`05`、`06`、`07`、`08`、`README`）
- **彻底解决 `04` 与 `05`/`06` 的状态定义冲突**：将原 `04` 合并的“类别 II”拆分为物理隔离的两轨——
  - **类别 II-A · `FACT_CONFLICT_CANDIDATE`（`high_risk_fact_alert`）**：进入 **`TempSafetyGate`（等待核实的临时安全门）**，核实为误报或合法叙事可解除放行，核实为真实错误进入修复或 `PLANNING_CONFLICT_BLOCK`；
  - **类别 II-B · `STALE_REVIEW_AFTER_EDIT`（`integrity_alert`）**：已定稿正文未经显式 `retcon` 被外部修改，属于**工程完整性破损**，立即进入 **`IntegrityHardBlock`（工程完整性硬阻断态）** 阻断新章写入，**严禁仅通过标记“误报”或“合法叙事”直接解除**，唯一合法恢复条件为“显式 `retcon`（或回滚快照）+ 对改动章及直接影响集重新审核 + 更新复合审读指纹与 `manuscriptHashes`”。
- **同步统一 Mermaid 流转图、状态枚举、触发/恢复条件与 E3/E4 验收用例**（`04`、`05`、`06`、`07`、`08`）。

### 3. P3 · 增强聚类统计的样本独立性要求（影响：`03`、`07`、`08`、`README`）
- **为 G1、G2、G3、G6 逐一明确样本三元组 `$N_{\text{ch}}$`（独立章节数）/ `$N_{\text{case}}$`（独立案例数）/ `$K_{\text{rep}}$`（重复运行次数）**：
  - G1：Track 2 `$N_{\text{ch}}=9, N_{\text{pos}}=40, K=3$`（明示 40 案例聚于 9 章，不等于 40 个独立章）+ 整章回归 `$N_{\text{ch}}=7, K=1$`；
  - G2：**`$N_{\text{ch}} >= 20$` 个独立来源章节（硬约束单章 `<= 3` 条非阻断案例、覆盖 `>= 3` 题材）** / `$N_{\text{neg}} >= 60$` / `$K = 3$`，并给出可执行样本构建设计；
  - G3：**`$N_{\text{ch}} >= 10$` 个独立来源章节（单章 `1–2` 段）** / `$N_{\text{case}} >= 15$` / `$K = 3$`，**强制同样采用章节级聚类 Bootstrap 95% CI**（不可只用普通案例级 CI）；
  - G6：4–6 题材 × `$N_{\text{ch}} = 12–16$` 独立完整章 / `$N_{\text{pos}} >= 30$` / `$N_{\text{neg}} >= 40$` / `$K = 1$`。
- **强化两条统计红线**：① 明确 `B = 2,000` 次 Bootstrap 只是数值重抽样计算，绝不能弥补独立章节数（$N_{\text{ch}}$）不足；② 明确 `12–16` 章不足以支撑全题材可靠统计学推断，将 G6 严格标记为**有限预算下的工程准入筛查（Budget-Constrained Engineering Admission Screening）**，严禁宣称统计学上证明了生产召回率达到 90%。

### 4. P4 · 强化 L0 绝对零写入验收（影响：`02`、`03`、`04`、`05`、`07`、`08`、`README`）
- **扩大静态审计范围**：覆盖直接写 API（`writeFile*`/`appendFile*`/`createWriteStream`/`mkdir*`/`mkdtemp*`/`rm*`/`unlink*`/`rmdir*`/`truncate*`/`chmod`/`chown`/`utimes`）、复制/移动/链接（`copyFile*`/`cp*`/`rename*`/`link*`/`symlink*`）、带写/创建/截断标志的 `open`/`openSync`/`fsPromises.open` 与 `fs.write*`/`FileHandle.write*`，以及间接写入与子进程逃逸（`child_process`、`eval`、`new Function`、动态 `import()`、直接/传递导入模块）。
- **建立三重零写入验证（静态扫描不能单独作为证明）**：① 扩大化静态审计；② **只读文件系统（`:ro` 挂载）或等效非特权 `chmod -R a-w` 隔离沙箱实测**（须 exit code `0`、零 `EROFS`/`EACCES`）；③ **运行前后全项目目录 `manifest_sha256` 比对（0 新增、0 删除、0 字节改动）**。
- **分别独立验证与编排层边界**：明确对 **`diagnose_book.mjs`** 与 **`audit_story_state.mjs --readonly`** 分别执行三重验证；明确 **`r3_ops.mjs`** 是唯一允许承接诊断缓存落盘的编排层，绝不因此放宽 L0 自身的只读要求。
