# 06 · 审核、修复、复审及版本失效协议

> **文档版本**：`v1.2.1 (Freeze-Ready Candidate)`  
> **协议定位**：为 R3 v3 定义无歧义、可机器核验、向后兼容 R2 的核心状态机与标准化 JSON 报告契约。覆盖 `precheck v2` 确定性阻断准入、三方案（A/B/C）兼容的审稿报告契约、复合审读指纹、Fail-Closed 完备性、S1 四级枚举与 `impactScope` 硬拦截、**`FACT_CONFLICT_CANDIDATE`（临时安全门）与 `STALE_REVIEW_AFTER_EDIT`（工程完整性硬阻断）严格分轨**、三元组跨轮继承、写手改动映射、3 轮瓶颈诊断、分层复审与显式 `retcon` 补偿协议。

## 一、确定性预检（`precheck v2`）阻断准入原则与输出契约

### 1. 严格阻断准入原则（防机械规则反噬创作）
`precheck_chapter.mjs v2` 严守**“只有工程文件破损与作者显式硬约束才允许确定性阻断”**原则：

| 检测类别 | 默认分级 | 是否允许阻断送审 | 规则说明 |
|---|---|:---:|---|
| **工程文件破损**（文件不存在/0 字节空稿、非法编码/二进制污染、未走 `retcon` 篡改已定稿文件） | `hardErrors` | ✅ **是** | 零 LLM 直接打回，**不递增 `revision`** |
| **作者显式硬约束**（作者在 `02-写作计划.json` `hardConstraints` 中明确配置的 `mustInclude` / `mustExclude` 或显式开启的 `enforceMinWords: true` 等硬条款） | `hardErrors` | ✅ **是（仅按作者显式配置生效）** | 借鉴 v8 `checks.ts` 硬约束三分类中的确定性两类（`出现`/`禁止`） |
| **字数偏离、引号不配对候选、整段重复候选、正文圆括号、高频突发副词、超长分号句** | `softWarnings` | ❌ **否（默认永不阻断）** | **严禁为了死磕字数牺牲内容完整性**；重复段/跨段引语/字数波动默认均不视为文学硬伤，仅作写手参考 |
| **语义待核线索**（日期/时辰差、账目/金额/数量变动、证物/道具编号序列、硬约束中的 `need_semantic_audit` 条款、高潮动作段标记、信息差敏感词） | `needsSemanticAudit` | ❌ **否（不阻断写手，但强制审稿核销）** | 自动注入审稿包，审稿报告必须逐条给出 `pass / issue_raised / insufficient_material` |

## 二、复合审读指纹、Fail-Closed 完备性与标准化审稿报告契约

### 1. 五元组复合审读指纹（`reviewFingerprint`）
在 R3 命名空间下升级为五元组复合指纹（同时原样保留 `manuscriptHashes` 确保 R2 旧项目 100% 兼容）：
```text
reviewFingerprint = sha256(canonicalJson({
  manuscriptSha256: <冻结正文原文 SHA-256>,
  planningSliceSha256: <本章细纲 + 核心契约 + 当前卷锚点切片 SHA-256>,
  ledgerSliceSha256: <截至 N-1 章的有效全局事实与上章 handoff SHA-256>,
  hardConstraintsHash: <02-写作计划.json 中作者显式硬约束配置哈希>,
  protocolVersion: "r3-review-v3.0"
}))
```

### 3. Fail-Closed 完备性规则与空增版本号修复
- **缺项硬拒收**：任意 6 维 `dimensionAuditSlots` 缺席、任意 `NEEDS_SEMANTIC_AUDIT` 未核销、`reviewFingerprint` 不匹配、`quote` 不存在于冻结正文、或 `BLOCKER/MAJOR` 缺少 `reverseDefense` / `impactScope` → `r3_ops.mjs apply-review` **硬拒绝落盘（exit code 2）**。
- **不空增 `revision` Bug 修复**：写手送审前调用 `precheck --dry-run` 或命中 `hardErrors` 自修时，**不冻结、不递增 `revision`**；仅确认送审并生成 `reviewFingerprint` 时才分配新 `revision`；遥测按实际提交的独立审稿报告数计量有效返工轮次。

### 4. 版本失效触发矩阵与两类阻断态严格分轨（`FACT_CONFLICT_CANDIDATE` vs `STALE_REVIEW_AFTER_EDIT`）

| 变更 / 告警事件 | L0 / 状态枚举 | 状态机路径与阻断行为 | 唯一合法恢复条件 |
|---|---|---|---|
| 待审正文改动 ≥1 字节 | `fingerprint_mismatch` | 自动重置当前未完成轮次 `reviewFingerprint`；旧报告不可用于本稿提交 | 重新冻结并重审当前稿 |
| 冻结规划或前置账本变化 | `STALE_CONTEXT_VERIFY`（`advise`） | 未定稿章强制重编审稿包并重审；已定稿章标 `advise` 提示复核 | 由 `analyze_impact.mjs` 界定受影响章后按需复核 |
| **高危事实冲突候选（`FACT_CONFLICT_CANDIDATE`）**（含结构化整数守恒失配候选） | **`high_risk_fact_alert`** | 发现当章立即进入 **`TempSafetyGate`（等待核实的临时安全门，非自动文学判决，绝不等 L2）**，暂缓开启第 $N+1$ 章 | ① 经独立核实/作者确认属**误报或合法叙事** → **允许解除安全门直接放行、不改正文**；<br>② 核实为**真实事实错误** → 进入当章定向修复或升级 `PLANNING_CONFLICT_BLOCK` |
| **已定稿正文未经显式 `retcon` 被外部修改（`STALE_REVIEW_AFTER_EDIT`）** | **`integrity_alert`** | 立即进入 **`IntegrityHardBlock`（工程完整性硬阻断态）**，**立即阻断一切新章写入**（与 `TempSafetyGate` 物理分离） | **严禁仅通过标记“误报”或“合法叙事”直接解除！**<br>必须完成三步恢复：① 补走显式 `retcon` 审批与快照留痕（或回滚至原已定稿快照）；② 对改动章及 `analyze_impact.mjs` 直接影响集完成重新审核；③ 更新复合审读指纹 `reviewFingerprint` 与 `manuscriptHashes` 至最新有效状态 |

## 三、S1 四级严重程度 × `impactScope` 硬拦截 × `PLANNING_CONFLICT_BLOCK`

### 1. S1 四级严重程度与阻断契约（向后兼容 R2 三级历史报告）

| 严重级别 | 定义边界 | 阻断单章通过 | `mustCloseInReReview` | 必附 `reverseDefense` | 兼容策略 |
|---|---|:---:|:---:|:---:|---|
| **`BLOCKER`** | 核心情节、基础世界律、会计/数学/三维空间彻底无法成立 | **是** | **是**（不可豁免） | **是** | R2/R3 原生兼容 |
| **`MAJOR`** | 明显损害普通读者理解、可信度、人物动机、限知 POV 或关键因果 | **是**（B 类弧内风险在启用分级时允许 `fix_in_arc`） | **是** | **是** | R2/R3 原生兼容 |
| **`MINOR`** | 局部事实/细节微瑕，不阻断单章理解与通过 | **否** | **否** | 否 | R2/R3 原生兼容 |
| **`SUGGESTION`** | 表达润色、节奏微调、可选文学增强建议 | **否（永不阻断）** | **否（0% 进必改闭环）** | 否 | **新增枚举**：须通过全仓下游消费者只读兼容审计（新读旧/旧读新双测） |

### 2. `impactScope` 硬拦截与 `OR6` 终极分层

| `impactScope` | 含义 | 允许混入写手改稿批？ | 强制流转路径 |
|---|---|:---:|---|
| `draft_only` | 正文实现偏离规划或正文内部自相矛盾 | ✅ **允许** | 编译纯叙事修订卡 → 写手定向改稿 → 复审 |
| `upstream_planning` | 正文字面遵守冻结大纲，但大纲自身存在客观数学/会计/空间/设定死锁（如 `V22-H4` 三千引悖论） | ❌ **工具硬拒绝混入写手改稿批！** | 直接输出 **`PLANNING_CONFLICT_BLOCK`** → 自动运行 `analyze_impact.mjs` → 向作者呈报 2–3 个修订候选与影响面 → 作者批准升版规划（`r3_plan.mjs`）→ 标记 `transferred_to_proposal` → 重审本章 |
| `finalized_canon` | 本章暴露前文已定稿章节存在既成事实错误 | ❌ **严禁静默覆写已定稿文件！** | 输出 **`PLANNING_CONFLICT_BLOCK (retcon_required)`** → `analyze_impact.mjs` 扫描影响集 → 作者批准后走显式 `retcon` 事务 |

> **`OR6` 终极分层**：大纲批准的合法创作桥段 → 归 `planningConflictAdvisories`（不阻断）；大纲自身客观死锁 → 强制 `impactScope = upstream_planning` + **`PLANNING_CONFLICT_BLOCK`**（0% 洗白为 `PASS`）。

## 四、跨轮三元组继承、改动映射与 3 轮瓶颈诊断协议

### 1. 跨轮语义三元组继承（带严格安全防线）
```text
issueIdentityKey = sha256(canonicalJson([
  dimension,
  normalizeAnchor(quoteAnchor),
  normalizeReasonKey(subject, key)
]))
```
- **仅在同时满足以下两条件时允许跨轮自动继承免报**：① 上一轮由**真实人类作者**明确批注为 `author_kept` / `author_rejected` / `transferred_to_proposal`（且关联提案已批准）；② **该条目所在段落的文本哈希未发生变化**。
- **严禁继承**：模型上一轮自判降级或放过的条目永不冒充作者保留；所在段落一经修改，旧豁免立即失效并强制重核。

### 2. 写手修订卡、改动映射与 3 轮瓶颈诊断
- **写手修订卡（语域防火墙输出）**：仅含 `preserveStrengths`（≤3 原句）+ 需修阻断项的自然语言说明与叙事化修改方向；**严禁出现 `reverseDefense`、JSON 字段名、门禁码或限时压迫词**。
- **改动映射清单**：写手交付修订稿时附带极简映射（`[ISS-001] → 第 14–16 段 → 一句话改动说明`，仅给主控与复审核验，不写入正文）。
- **3 轮上限 + 瓶颈诊断**：同一章经历 **3 轮有效编辑返工**（不含本地预检）仍未通过时强制停机，主控提交《单章瓶颈诊断卡》（卡点维度分布 + 根因归属：写手执行 vs 上游规划过紧 + 作者有限决策选项）。

## 五、分层复审策略与显式 `retcon` 最小协议

### 1. 三轨复审策略（拒绝零复审，拒绝盲目全冷审）

| 触发条件 | 复审模式 | 检查范围与要求 | 耗时参考 |
|---|---|---|---|
| **小幅定向修复**（`diffChangedRatio <= 30%` 且非第 2 次打回且未改核心因果/设定且同 3 章窗口暖会话有效） | **Track A：热复用差分聚焦复审 + 亮点回归扫查** | 必跑 `precheck v2`；暖编辑核验 `diff.md` + 变更点上下各 2 段 + 改动映射闭环 + `revisionProtection` + 快速通扫全文 | `~1.4–2.5 min`（参考 Arm 2 实测 `1.87m`） |
| **大改 / 熔断重置**（`diffChangedRatio > 30%`、单章打回 ≥2 次、跨 3 章窗口、累计热审 ≥6 轮、或上游规划修订后重审） | **Track B：全新冷启动完整复审** | 销毁旧热会话，新建冷启动独立编辑执行完整全章复审（继承作者已批注三元组） | `~5.0–7.5 min`（参考冷复审实测 `6.53m`） |
| **纯作者处置无正文改动**（正文与上下文指纹零变化且无未决阻断项） | **Track C：免重审放行** | 仅校验复合指纹未变与处置完备 | `<1s` |

### 2. 显式 `retcon`（已定稿回改补偿）最小协议
1. **前置取证**：只读运行 `analyze_impact.mjs --chapter k --changed-facts <ids>` 输出直接影响集与候选影响集；
2. **真实作者批准**：呈报修改原因、差异与影响范围，落盘 `reviews/r3/retcons/retcon-NNN-approval.json`；
3. **快照留痕**：修改前由 `r3_snapshots.mjs` 自动固化原章与 `story-ledger.json` 只读快照（永不无痕覆写）；
4. **受控写入与定向回归**：仅改授权段落，在 `story-ledger.json` 中用 `supersededBy` 显式标记旧事实被替代，随后对第 $k$ 章及 `directImpactChapters` 执行聚焦回归复审。
