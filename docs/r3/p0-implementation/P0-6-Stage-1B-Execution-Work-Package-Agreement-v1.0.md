## 三、六个正式工作包（WP1–WP6）

### WP1：历史素材盘点与真实缺口核算

- **主责**：Neon
- **协作**：GPT-6（有限独立复核）、作者（动态预算审批）
- **目标**：完成前置管理状态同步，优先盘点并复用已存在且符合独立性要求的历史素材，避免重复创作。

#### Neon 工作内容

0. **前置管理状态同步（依据 `v0.2.5` §9）**：将 [`P0-Implementation-PRD.md`](./P0-Implementation-PRD.md) §五 及总验收表中 `P0-5` 的状态由 `NOT_STARTED` 同步为已 `ACCEPTED`（关联 Issue `#9` Comment `7209790256`）；**严格限定仅更新 `P0-5` 状态字段，不修改任何任务定义、验收标准或冻结要求**。
1. 盘点所有可访问的历史素材及暴露记录。
2. 建立历史暴露注册表，记录原始与规范化 SHA-256。
3. 对历史素材进行六维独立性及近似重复核查。
4. 按冻结规则将全部素材归入五种状态：
   - `ELIGIBLE_ASSIGNED`
   - `EXCLUDED_EXPOSED`
   - `EXCLUDED_UNKNOWN`
   - `RESERVE`
   - `UNASSIGNED`
5. 建立全局唯一分配清册：`00c-global-asset-allocation-v1-historical.json`。
6. 执行 G4 确定性 `Mulberry32`（连续 PRNG 流 + Fisher–Yates）预注册选样。
7. 计算各门禁真实缺口及动态预算：

$$\Delta N_g = \max(0, \; T_g - R_g)$$

其中：
- $T_g$：门禁 $g$ 的目标样本数量；
- $R_g$：门禁 $g$ 符合条件的历史可复用样本数量。

`unknown` 素材按 Fail-Closed 原则严格禁止进入 `G2-B` / `G6`。

#### WP1 数据保管与脱敏公开边界（Vault vs. 复核/公开数据）

> 原则：GPT-6 的独立复核不需要、也不应接触全部敏感原始材料；主仓始终维持 0 字节原始小说正文。

| 数据类别 | 唯一允许保存/流转位置 |
|---|---|
| 原始小说正文 | **仅限 Project A 本地 Vault**（严禁入仓、严禁发送至公开 Issue） |
| 完整历史暴露记录 | **仅限 Project A 本地 Vault** |
| 原始题名、本地路径、真实来源映射 | **仅限 Project A 本地 Vault** |
| 脱敏 ID、五态计数、唯一历史例外校验摘要 | 可提供 GPT-6 独立复核 |
| 脱敏真实缺口表、动态预算单、G4 预注册脱敏索引 | 可提供 GPT-6 独立复核 |
| 脱敏汇总摘要与复核结论 | 可记录在 GitHub Issue `#10` |

#### GPT-6 工作内容

对 Neon 提供的**脱敏材料**进行一次独立复核：

- 清册分配逻辑与五态覆盖完整性；
- 各门禁真实缺口计算（$\Delta N_g$）与唯一历史例外（`EXC-HIST-QHL-G3-G4`）；
- 样本去重与六维互斥规则执行记录；
- 预算算术及与 D1–D5 目标数量的一致性。

复核不涉及未脱敏正文、原始真值及离线密钥；采用**一次正式复核 + 有限客观错误修正**机制，不重新展开已经冻结的 `v0.2.5` 设计讨论。

#### 交付物

- `P0-Implementation-PRD.md` 中 `P0-5` 状态同步提交（仅状态字段）；
- 历史暴露注册表与历史素材统一盘点表（完整原件存 Project A Vault，脱敏汇总供复核）；
- `00c-global-asset-allocation-v1-historical.json`（完整版存 Vault，脱敏版供复核）；
- G4 预注册随机选样记录；
- 各门禁真实缺口表与动态预算单；
- GPT-6 独立复核结论。

#### 验收条件

- 全部已盘点素材均有明确五态审计去向，无遗漏；
- 不存在未经说明的跨门禁重复分配；
- 唯一历史跨门禁例外严格遵循 `v0.2.5`（仅限 `QHL-CH1..3` 用于 `G3`/`G4`）；
- `G2-B` / `G6` 不存在任何 `unknown` 素材；
- 各门禁缺口及预算计算可复现；
- 作者批准动态预算后，方可进入 WP2。

### WP2：GPT-6 全新挑战语料补创

- **主责**：GPT-6
- **协作**：Neon（标准任务单、机械预检）、作者（文件中转）
- **目标**：仅针对 WP1 确认并获作者批准的真实缺口补充全新挑战章节，不重复制造已有样本。

#### Neon 工作内容

WP1 获批后，向 GPT-6 提供标准化创作任务单与校验 Schema，至少包含：

1. 各门禁真实缺口数量（来自已获批的 $\Delta N_g$，不得提前虚构）；
2. 题材与流派精确分配要求；
3. 各严重程度（`BLOCKER`、`MAJOR`、`CLEAR`、`BORDERLINE` 等）逐章案例配额；
4. 故事背景、细纲、账本及必要上下文骨架；
5. 创作约束及禁止事项（含防暴露与防模板化约束）；
6. 统一交付 Schema 与机械预检脚本规则说明；
7. 命名与唯一 `sourceWorkId`、`sourceChapterId` 规则；
8. 六维去重与结构完整性预检标准。

#### GPT-6 工作内容

按照任务单**按门禁分批创作交付（建议每批 4–6 章，避免单轮输出截断）**，每批包含：

- 全新故事章节正文；
- 预期缺陷及精确案例位置设计；
- `creatorIntendedLabel` 标注；
- 预期严重程度及客观判定依据；
- 唯一 `sourceWorkId`、`sourceChapterId`；
- 批次交付 Manifest 与逐文件 SHA-256（全部批次完成后汇总总 Manifest）。

#### 物理交接路径与机械预检退回闭环

GPT-6 与 Project A VM 不存在直接文件写入通道，固定采用以下闭环：

1. Neon 生成标准任务单与校验 Schema，交作者转发 GPT-6；
2. GPT-6 按门禁分批交付标准格式单文件语料包（每批建议 4–6 章）及 Manifest/SHA-256；
3. 作者下载批次包并上传至 Project A；
4. Neon 将文件落盘至 Project A 本地 Vault `01-raw-corpus/`，并执行**两类分级预检**（严禁演变为文学优劣主观评价）：
   - **A. 确定性硬失败（自动进入退回闭环）**：ID 缺失或相同 `sourceWorkId` 冲突、原始/规范化哈希精确重复、Schema 不符、数量/逐章配额不符、案例位置缺失、标签字段不完整、哈希或文件结构异常；
   - **B. 近似重复预警（`HOLD / MANUAL_REVIEW_REQUIRED`，不自动拒收）**：若仅触发六维近似重复相似度预警，不得自动认定污染或自动要求 GPT-6 替换章节，先挂起进入人工复核；**仅经人工复核确认为改写/复制后才正式拒绝并转入退回闭环**；若核实属独立创作中的行业常规表达，须书面记录放行依据后放行；
5. **预检退回机制**：仅对「确定性硬失败」及「人工复核确认污染的近似重复项」，Neon 输出结构化退回报告 `precheck-rejection-report.json`（仅列违规 ID、客观规则项或人工确认结论）→ 作者转发 GPT-6 → GPT-6 **仅修复或替换退回章节**并重新提交，直至全部批次通过；
6. **版本不可覆盖与重审硬规**：每次修订必须以 append-only 方式保留**原始交付版本、退回记录及新版本 SHA-256**，严禁静默覆盖历史交付；**一旦某章节进入 WP3 独立真值定案，后续任何正文修改均须触发该章节完整重新评审**。

不得在任何文档中描述不存在的跨 VM 直接写入能力。

#### 交付物

- 分批及汇总全新章节语料包（落盘 Project A 本地 Vault `01-raw-corpus/`）；
- `creatorIntendedLabel` 及预期缺陷映射；
- 唯一 ID 清单、各批与最终汇总 Manifest 及 SHA-256；
- Neon 机械预检报告、近似重复人工复核/放行记录（如有）及 `precheck-rejection-report.json` 闭环记录；
- 按门禁和题材分类的脱敏交付统计。

#### 验收条件

- 交付数量、题材与案例配额与已批准的真实缺口 100% 一致；
- 唯一 ID 与精确哈希无冲突，全部近似重复预警均有明确人工复核结论（确认污染已替换或书面记录放行依据，零未决 `HOLD` 项）；
- 所有预期案例均有明确位置、标签与严重程度；
- Neon 确定性预检 100% 通过且全部版本/退回历史完整留痕；
- GPT-6 不参与后续自创章节的真值裁决。

### WP3：独立 Gold Standard 定案

- **组织主责**：Neon
- **实际定案**：独立 Judge 1 / Judge 2 / Arbiter 3
- **作者**：DQ-4 强制人工复核与 `v2-final` 批准

#### 评审运行方式与同 VM 隔离诚实边界

默认采用 Project A 内 Antigravity 独立冷启动子代理（`Judge 1` 独立盲审、`Judge 2` 独立盲审、`Arbiter 3` 按预注册规则独立仲裁），执行以下最小权限约束与诚实边界声明：

1. **输入最小化**：每个评委子代理使用独立冷启动会话，不继承 Neon 主对话上下文；仅通过内联 Prompt 接收**单章匿名正文、必要规划切片与 Rubric**，严禁传入 `creatorIntendedLabel`、`corpusOrigin`、Vault 路径或其他评委未提交判断；
2. **工具权限最小化（基于平台实际支持的控制项）**：按当前 Antigravity 官方及实际运行环境支持的工具允许列表（`tools` allowlist）、命令执行策略（`commandExecutionPolicy`）及 `mcpServers` 配置，仅授予评委完成内联评审所必需的最小能力（不授予写文件、终端执行、MCP 或非必要工具），不挂载、不提供 Vault 敏感目录，并指令评委零工具调用纯文本输出评审结果；**在 WP3 正式建集启动前须核查并归档子代理实际生效的工具清单**，不得将未经平台验证确认的配置字段写成已落实的权限隔离；
3. **诚实隔离边界（严禁夸大）**：Antigravity 官方文档明确子代理会继承父代理的文件读写范围与沙箱设置，因此 **`transcript.jsonl` 未记录文件读取仅作为辅助工具调用轨迹，绝不能作为「零文件访问」的证明**；本方案明确界定为**「会话与 Prompt 级逻辑隔离（非跨 Project VM 隔离）」**，对平台当前无法验证的底层文件访问隔离能力**如实标记为 `未验证`**，并按 `v0.2.5` §4.3 如实披露同模型家族相关性；
4. **可选升级路径**：如作者在开工前决定需要更强的访问隔离或跨模型家族独立性，可选用外部模型 API 或人工评委方案替代；若执行中平台无法提供满足基本独立会话要求的运行条件，应暂停该批次并交作者决策，不得擅自降低独立性或包装未验证能力。

#### Neon 工作内容

1. 准备统一匿名盲审材料，确保评委仅获得允许接触的内联内容；
2. 组织 Step A 完整章节开放盲审并归并 `openFindings[]`；
3. 组织 Step B 案例级结构化标定，按预注册规则将争议提交 `Arbiter 3`；
4. 完整归档全部评委配置（含 WP3 启动前实测生效工具清单）、原始盲审输出、哈希及辅助 `transcript.jsonl`；
5. 计算 DQ-1 至 DQ-4 指标并生成 append-only `00c-global-asset-allocation-v2-final.json`。

特别要求：
- G4 全部 `24` 例均须完成原始独立盲标，历史真值不得覆盖；
- 预期正例被降级必须完整留痕；
- FIFO 替补只能严格依照预注册顺序及原始 `creatorIntendedLabel` 类别键执行；
- GPT-6 严格回避自己创作章节的真值定案。

#### 建集期数据质量门禁（与 G1–G6 模型门槛严格区分）
